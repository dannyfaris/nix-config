# Host-registration binding — bind the flake's host surfaces to `hosts/` so a host cannot fall silently out of CI

**Status:** Proposed — design note (docs/design/). Build-state: complete (single slice, landed with this note). #710 · extends the #583 census-binding direction; no ADR.

## Summary

Four hand-maintained surfaces must name the same fleet — the `hosts/<name>/` directories, the flake registrations (`parts/nixos.nix` / `parts/darwin.nix`), the per-host `host-<name>` build check, and the per-host `stances-<name>` eval check (both in `parts/checks.nix`) — and today nothing binds them, so a host can be registered and built while silently absent from the deliberate-stance net, or linger as a check after its directory is gone. This note adds an eval-time `nix flake check` entry, `hosts-registration`, that reads the four surfaces as attr-name/dir-name sets and reports every disagreement as a human-legible failure naming the host and the exact file+fix. The set-diff is a pure function (`lib/host-registration.nix`) with its own unit-test check (`lib-host-registration`), mirroring the `lib/stances.nix` + `lib/tests/` + `mkReportCheck`/`mkUnitTestCheck` machinery already in the flake. It is eval, not a `grep`-class shell lint — the deliberate departure from #583's shell hook — because the right-hand side here is Nix data that `builtins.attrNames` reads directly and formatting-immune, where a line-oriented grep is defeated by the nixfmt-wrapped `stances-*` entries.

## Motivation

The entry surfaces of a host are spread across four files and bound only by convention. Adding a host means creating `hosts/<name>/`, registering it in `parts/nixos.nix` (NixOS) or `parts/darwin.nix` (Darwin), and adding two lines to `parts/checks.nix`: a `host-<name>` toplevel build and a `stances-<name>` deliberate-stance eval check. Retiring one means removing all four. Nothing checks that the four agree, and the most damaging drift is invisible: a host that is registered and given a `host-<name>` build check but *not* a `stances-<name>` check compiles green, auto-merges, and is silently exempt from the very stance net (`users.mutableUsers = false`, the SSH posture, the unfree whitelist) that CLAUDE.md §"Deliberate stances" declares non-negotiable. The build check answers "does it compile?"; only the stance check answers "does it still hold the guarantees?" — and a host can have the first without the second with no signal anywhere.

This is the same failure class #583 addressed for CLAUDE.md's prose host census — an entry-point surface that no PR is obligated to touch, so it rots — but #583 bound only the *prose* half (`hosts/` ↔ the census bullets). The *flake-data* half (`hosts/` ↔ the registrations ↔ the checks) is the half that actually gates CI, and it was left unbound.

The forces any design must honour:

- **F1 — Catch the invisible orphan.** The load-bearing case is registered-but-no-`stances-` check; a design that only checks dir↔registration misses it.
- **F2 — Formatting-immune.** The RHS (`parts/checks.nix`) is nixfmt-wrapped: `stances-metis` is one line, `stances-alcyone/alnair/electra` span three each. Any mechanism keyed on source-line shape is defeated by the formatter that CI itself enforces.
- **F3 — Platform-correct.** NixOS hosts live under `checks.x86_64-linux`, Darwin under `checks.aarch64-darwin`; a `host-neptune` mistakenly placed on the linux leg must be caught, not accepted.
- **F4 — Proportionate (ADR-032 Rule 1).** The lightest mechanism that *holds* the guarantee — where "holds" is decisive, because the candidate mechanisms do not hold the same guarantee.
- **F5 — Policy in the flake (ADR-025).** The check is a flake output reproducible with `nix flake check` / `nix build .#checks.x86_64-linux.hosts-registration`, and lands in the docs-only `checks-without-hosts` set automatically.
- **F6 — Actionable failures.** A failure must name the host *and* the file and the exact line to add or remove — the census lint's voice — not just report a set difference.

## Design

The check compares four surfaces as sets, partitioned by platform. Let, for platform P ∈ {nixos → x86_64-linux, darwin → aarch64-darwin}: `D` = the `hosts/<name>/` directory set (`builtins.readDir ../hosts` filtered to type `"directory"`); `R_P` = the registration set (`builtins.attrNames self.nixosConfigurations` / `self.darwinConfigurations`); `Chost_P` = the `host-`-prefixed slice of `builtins.attrNames self.checks.<system_P>` with the prefix stripped; `Cstance_P` = the `stances-`-prefixed slice likewise. A `hosts/<name>/` dir carries no intrinsic platform tag, so registration is the platform authority: the dir set is asserted against the *union* of both registrations, and the per-platform check assertions key off which registration claimed the name.

The pure function `lib/host-registration.nix` takes `{ dirs, nixosRegs, darwinRegs, nixosChecks, darwinChecks }` and returns a list of failure strings (empty ⇒ agreement) built from these set-diffs: (1) `D` vs `R_nixos ∪ R_darwin` — a dir with no registration, and a registration with no dir; (2) for each P, `R_P` vs `Chost_P` — registered but no `host-` build check; (3) for each P, `R_P` vs `Cstance_P` — registered but no `stances-` check (the F1 orphan); (4) cross-platform placement — a `host-`/`stances-` check for one platform's host appearing under the other platform's check set; plus stray `host-`/`stances-` checks whose name is registered on neither platform (a leftover after a half-done retirement). `parts/checks.nix` feeds it the real `readDir`/`attrNames` values on the x86_64-linux leg only — the set-diff is fleet-global data that reads both `nixosConfigurations` and `darwinConfigurations` and both legs' check names (all readable from a single linux eval), so like the keybind/lib checks it rides one runner rather than duplicating per-platform.

Each failure is emitted in the census lint's voice — it names the host and the file and gives the verbatim line to add or remove. For example, a registered host with no stance check yields: `alcyone is in parts/nixos.nix but has no stances-alcyone check → add `stances-alcyone = mkStanceCheck "x86_64-linux" "nixos" "alcyone" self.nixosConfigurations.alcyone.config;` to parts/checks.nix`. These strings feed `mkReportCheck`, which renders an empty list to a trivial success derivation and a non-empty list to a build that prints the report and exits 1 — the same harness `stances-*` and the keybind lints already use.

The check is named `hosts-registration` (plural), **not** `host-registration`: `mkChecksWithoutHosts` filters `hasPrefix "host-"` to build the docs-only cheap check set, and `host-registration` would be wrongly excluded from it. `"hosts-registration"` does not match the `"host-"` prefix (the dash falls after `hosts`, not `host`), so it survives the filter and gates docs-only PRs too. The self-test wires as `lib-host-registration = mkUnitTestCheck ...` alongside `lib-auto-gen-paths`/`lib-capabilities`, with eleven fixtures perturbing a clean-fleet baseline by one edit each — dir-orphan, registration-orphan, missing `host-`, missing `stances-` (both platforms), wrong-platform placement, multiple simultaneous drifts, empty fleet, and a prefix-pair (`metis` vs `metis-2`) that a substring match would wrongly mask.

This meets the forces: F1 via assertion (3); F2 because `attrNames` reads keys, not source lines, so nixfmt reflow is invisible to it; F3 via assertion (4); F4 because eval reads the truth where grep reads a rendering of it (see Rationale); F5 because it is a flake output surviving the `host-` filter; F6 by the census-voice strings.

## De-risk evidence

The load-bearing assumptions were verified on this aarch64-darwin box against the flake at branch `hosts-registration-710` before the check was wired.

- **`attrNames` extraction is cheap and forces no derivation.** `builtins.attrNames self.nixosConfigurations` → `[ "alcyone" "alnair" "electra" "metis" ]`, `darwinConfigurations` → `[ "neptune" "saturn" ]`, and `builtins.readDir ../hosts` → all six as type `"directory"`, all evaluated instantly. Reading keys does not force `.config.system.build.toplevel`, so the check lands in the cheap eval tier, not the per-host build tier.
- **`checks.aarch64-darwin` is readable from the linux-leg eval without instantiating darwin derivations.** `builtins.attrNames self.checks.aarch64-darwin` → `[ "host-neptune" "host-saturn" "pre-commit" "stances-neptune" "stances-saturn" "treefmt" ]` evaluated cleanly from this box. This is what lets the whole check ride x86_64-linux once.
- **`hosts-registration` is formatting-immune.** The real fleet's failure list evaluates to `[ ]` (agreement). The negative probe — commenting out `host-electra` in `parts/checks.nix` (worktree only) — produced exactly one failure, `electra is in parts/nixos.nix but has no host-electra build check → … parts/checks.nix (flake.checks.x86_64-linux)`, carried into the fail-path derivation's `report` (`exit 1`, `passAsFile`). Reverted cleanly (the diff shows no electra change).
- **The `hosts-` name survives the `host-` filter.** The `checks-without-hosts` linkFarm derivation's entries include both `hosts-registration` and `lib-host-registration` and exclude every `host-*` build — confirmed by reading the linkFarm derivation, so the plural name is not eaten by `mkChecksWithoutHosts`.
- **The atomic-scaffold trail refutes the bootstrap-window hypothesis.** The issue body hypothesised that "a host dir typically lands one PR before its full registration". The real trail refutes it: the scaffold commit — the first commit of each host — atomically touches `hosts/<name>/{default,disko,hardware-configuration}.nix`, `parts/nixos.nix` (+1), and `parts/checks.nix` (+4) in a single commit (electra `f109a46`, alcyone `2c35ae1`, both verified with `git show --stat`). No transient dir-without-registration window exists, so no bootstrap exemption is warranted.

Not verified here: the x86_64-linux build of the success and fail derivations could not be *run* on this aarch64-darwin box (no x86_64 builder available) — but both were shown to *evaluate* to the correct `runCommand` (success echo vs `exit 1` report), which is the whole of the check's logic; the runtime is a trivial `cat`/`echo`. CI's x86_64-linux leg is the enforcement point.

## Drawbacks

It adds a fourth binding surface to maintain, and — like #583 — it binds *names only*: it cannot see that `foo = mkHost { hostname = "bar"; }` disagrees with its attr key, nor that a `mkStanceCheck` host-string arg drifted from its check name. A reader might reasonably expect a "host-registration" check to catch exactly that. The honest position is that catching it needs source-parsing (grep's failing ground here) or forcing config eval, and #583 drew the same line; the gap is recorded below rather than papered over.

The check also reads the worktree (`readDir`), not the git index, so it differs subtly from the census lint's `git ls-files`. In CI (clean checkout) the two agree, which is the enforcement point; the divergence only surfaces for uncommitted local state, where `nix flake check` is not the gate anyway.

Doing nothing was a live option — the atomic-scaffold workflow means the surfaces are, in practice, kept in agreement by discipline. What defeats it is that the discipline is unenforced and the worst drift (missing `stances-`) is invisible, which is precisely the #583 argument one layer down.

## Rationale & alternatives

The mechanism fork was grep-over-`parts/*.nix` vs eval-time `attrNames` vs a hybrid, adjudicated in an operator-gated design loop. **Grep — rejected.** ADR-032 asks for the lightest mechanism *that holds the guarantee*, and grep does not hold it here: the RHS is a nixfmt-wrapped Nix attrset (F2), so a line-oriented match against the `stances-*` token cannot assert what it needs to, and buys fragility plus a coverage hole. #583's grep works because its RHS is markdown bullets — a stable line shape; #710's RHS is Nix data, where grep reads a *rendering* and eval reads the *truth*, formatting-immune. **Eval — chosen.** `builtins.attrNames` is immune to nixfmt reflow, cheap (forces no derivation), needs no shell portability surface (no GNU-vs-BSD `grep`/`sed`), and drops straight into the existing `mkReportCheck` harness. **Hybrid — rejected** as two mechanisms for one guarantee, unrequested complexity against "lightest that holds". The operator rulings settled three forks: mechanism = eval via `mkReportCheck`, not a grep lint (evidence: the nixfmt-wrapped `stances-*` entries defeat line-oriented grep; `attrNames` is formatting-immune); strictness = strict two-way agreement across all four surfaces with **no** bootstrap exemption (evidence: the atomic scaffold trail above refutes the transient-window hypothesis); scope = names-only, with hostname-string arg drift an accepted gap (mirroring #583).

This is a deliberate divergence from #583's shell hook: the two are structural siblings in the *guarantee* (set-agreement between `hosts/` and a hand-maintained surface), not in the *mechanism*. #583 is a pre-commit shell hook because its RHS is markdown that no eval reaches; #710 is an eval check because its RHS is Nix data that eval reaches natively. The impact of doing nothing is the invisible-orphan risk left standing — a host silently outside the stance net — which is the exact class #583 exists to prevent, one layer deeper.

## Prior art

#583 (`scripts/lint-host-census.sh`) is the direct predecessor: the same two-way set-agreement intent, the same names-only scope boundary, the same census failure voice — this note reuses all three and diverges only on mechanism (eval vs shell) for the reason above. The `mkReportCheck` / `mkUnitTestCheck` harness and the `lib/*.nix` + `lib/tests/*.nix` pure-function-plus-unit-test shape come from `lib/stances.nix` and `lib/tests/capabilities.nix` under ADR-033 — this check is another instance of that pattern, not new plumbing. The keybind collision lints (`lib/capabilities.nix`, ADR-039) are the precedent for a fleet-global eval check riding the x86_64-linux runner once rather than per host.

## Unresolved questions

**Accepted gap (names-only, Fork 3):** the check compares attr names only, so attr-key ↔ hostname-string drift inside a registration (`foo = mkHost { hostname = "bar"; }`) and a wrong `mkStanceCheck` host-string arg are *not* caught. This is a consciously-accepted boundary mirroring #583's own names-only call; closing it would require source-parsing or forced config eval, and is out of scope for this slice.

**`readDir` worktree vs git index:** the dir set comes from `builtins.readDir ../hosts` (the worktree), where the census lint reads the git index (`git ls-files`). They diverge only for uncommitted/untracked directories; in CI's clean checkout they agree, and CI is the enforcement point. `readDir` is the pure-eval-native primitive and pulling it toward index-parity would argue back toward a hook, which the mechanism fork rejected.

## Future possibilities

If attr-key ↔ hostname-string drift ever bites in practice, the names-only gap is the natural place to extend — but that is an evidence-triggered move (ADR-032), not a speculative one, and it changes the mechanism class (parsing or forced eval), so it warrants its own note rather than a quiet widening here. Should a fleet registry ever be minted (the #562 registry-carrier direction), this check's four set-diffs become derivable from one source and the hand-maintenance it guards against largely disappears; until then the guard is the proportionate rung.
