# Noctalia v5 migration — re-integrating the fleet shell against the native rewrite

**Status:** Accepted (2026-07-25) — design note (`docs/design/`). Not built. [#644](https://github.com/dannyfaris/nix-config/issues/644) (the migration) · [#631](https://github.com/dannyfaris/nix-config/issues/631) (Alcyone bootstrap, gated on this) · amends [ADR-044](../decisions/ADR-044-linux-runtime-theme-menu.md) (the Noctalia palette-delivery seam — its recorded v5 migration trigger has fired) · [ADR-036](../decisions/ADR-036-noctalia-shell-linux-desktop.md)'s shell-adoption role is unchanged, but its v4 mechanics (Quickshell runtime, `settings.json` posture, `noctalia-shell` IPC) are superseded by this note.

## Summary

Migrate the Linux desktop's Noctalia shell from v4 (the frozen `legacy-v4` Quickshell line) to v5.0.0-beta.4 (the ground-up native C++ rewrite) in a single cutover, validated live on metis ahead of the Alcyone bootstrap. This is a re-integration, not a version bump, and four decisions ride on it. (1) ADR-044's themed-by-Nix seam is re-expressed against v5's palette system: v4's watched `colors.json` no longer exists, so the conductor's palette takes over that slot in the per-target resolved-symlink set — a constant-name custom palette (`~/.config/noctalia/palettes/theme-menu.json` → state → per-family store artefact carrying `dark` + `light` + `terminal` blocks) that the `theme` CLI activates by explicit trigger (`noctalia msg config-reload`, or `theme-mode-set` on polarity changes), so the family selection continues to live in exactly one place, the conductor's pointer. (2) The Nix config posture becomes a minimal declared baseline: v5 layers a read-only declarative `config.toml` under a runtime GUI-overrides file, dissolving v4's GUI-managed-XOR-Nix-pinned trade — theming wiring, idle, and posture toggles are declared; look and layout stay GUI-managed runtime state. (3) Idle→suspend is enabled — a deliberate stance change, retiring "no auto-suspend on a desktop", validated on metis because Alcyone needs it proven. (4) The lock-before-sleep guarantee that the v4 gap relaxed is restored via a before-sleep hook, now that v5 honours `loginctl lock-session`. Alcyone inherits the proven configuration rather than debugging a beta rewrite mid-bring-up.

## Motivation

The v4 line is frozen into maintenance upstream and was adopted as a known waypoint (ADR-036 recorded "v5 leaves alpha" as a migration trigger — though its full wording asks for a *stable* tag, so moving at beta.4 is ahead of the letter of that trigger; §Drawbacks carries the argument). v5 is now at beta.4 and Alcyone (#631) — the fleet's first discrete-GPU desktop — is meant to run v5 from first boot, so the fleet shell must migrate and be proven on metis, the live, attended desktop with generation-rollback break-glass, before Alcyone bootstraps onto it.

v5 is a from-scratch rewrite, and the integration surface moves under every piece of our wiring. The Quickshell/Qt runtime is gone (a native meson-built binary, `noctalia`, replacing the co-locked `noctalia-qs` fork). The home-manager namespace renames (`programs.noctalia-shell` → `programs.noctalia`). Config moves JSON→TOML with no v4 importer — the operator's GUI-managed `settings.json` state does not carry over. The IPC grammar changes wholesale (`noctalia-shell ipc call …` → `noctalia msg …`), which our niri launcher keybind and spawn line depend on. And the seam ADR-044 built its Noctalia delivery on — the FileView-watched `~/.config/noctalia/colors.json` — has no v5 read path at all: source-verified at the tag, nothing in v5 reads that file, palette JSON files are not hot-reloaded (inotify covers only `*.toml`), and v5's own chrome colours resolve in-process from `[theme]` config. ADR-044's recorded migration trigger — "if Noctalia v5 changes how it reads colors.json (path, trigger, format), update the seed + CLI accordingly" — has fired on all three axes at once.

The migration is therefore also an opportunity to fix what v4 forced. The copy-into-place delivery existed only because v4's watchers could not see symlink swaps; with no palette watcher in v5, every repaint is explicitly triggered anyway, and the palette can join the same per-target resolved-symlink pattern every other conductor artefact already uses. Likewise v4 forced an either/or between GUI-managed and Nix-pinned settings; v5's config layering (read-only `config.toml` + runtime `settings.toml` overrides, where all GUI and IPC writes land) supports a declared reproducible core under mutable runtime cosmetics. And v4 could not honour an external lock request; v5 honours logind's session Lock signal, making the relaxed lock-before-sleep guarantee restorable.

An adversarial review of the palette seam (2026-07-25, recorded in §De-risk evidence) sharpened the central lesson into a force in its own right: the reviewed-and-rejected alternative delivered Noctalia the *name* of the active family over IPC, and because v5 persists every theme IPC write into its GUI-owned overrides file, that duplicated the live selection into state Nix cannot reach — the exact pathology ADR-044 was written to kill, recreated one layer down.

**Forces — what any design here must satisfy:**

- **Nix is the single theming authority (ADR-044).** Noctalia remains a themed-by-Nix shell; the migration must not quietly re-expand Noctalia's authority over colour, and v5's template engine stays off — the conductor owns every external surface.
- **Each selection lives in exactly one place; consumers receive a dereference, never a copy.** The family axis is the conductor's symlink pointer, the polarity axis is the dconf key. No mechanism may duplicate a live selection into state the conductor does not own — not a copied file (the v4 shape), and not a persisted IPC echo (the rejected v5 shape).
- **Runtime selection is sacred.** Live family + polarity switching with no rebuild; a rebuild never stomps a live selection (ADR-044's seed-if-absent rule carries over).
- **Reproducible boot default.** A fresh provision lands on the declared family/polarity with no GUI step.
- **Minimal declarative baseline** (operator call, 2026-07-25). Theming wiring, idle behaviours, and posture toggles are Nix-declared; look, layout, and cosmetics stay runtime/GUI-managed in v5's overrides layer. Declared core, mutable skin.
- **Explicit triggers, no assumed watches.** ADR-044's hard-won rule: no passive file-watch is assumed for any surface without runtime verification. v5 has no palette watcher at all, so every repaint path must be explicitly fired — and proven on metis, not inferred from source.
- **Beta upstream, smallest seam surface.** Pin the release tag (`v5.0.0-beta.4`, never `main`); minimise the count of upstream-facing seams (IPC verbs, schema shapes, override semantics) the design depends on; record migration triggers for what beta→stable may move.
- **metis proves it before Alcyone builds on it.** Every claimed runtime behaviour — repaint, lock, suspend, persistence — is validated on metis (set ≠ enforced); Alcyone inherits results, not assumptions. Generation rollback is the break-glass.
- **Two stance changes are named, not smuggled.** Idle→suspend retires the recorded "no auto-suspend on a desktop" posture, and the restored lock-before-sleep guarantee reverses the v4 accepted gap — both are deliberate reversals of previously-recorded decisions and must read as such. The suspend stance must additionally coexist with metis's reality as a remotely-used box (SSH sessions and agent workloads are invisible to Wayland idle detection), so the design must confront wake-ability and remote-activity guarding rather than assume an attended desktop.

## Design

### Flake input and module

`inputs.noctalia` moves to `github:noctalia-dev/noctalia/v5.0.0-beta.4` — the renamed upstream repo, pinned to the release tag (never `main`; v5 is beta and `main` moves daily). `inputs.nixpkgs.follows = "nixpkgs"` stays per convention; no binary cache exists for v5 in-repo, so the meson/C++ build is local either way (a far lighter build than v4's Qt). The co-locked `noctalia-qs` runtime disappears with the bump — it was internal to the v4 flake, not an input of ours.

`home/nixos/noctalia-shell.nix` is renamed `home/nixos/noctalia.nix` (the binary and HM namespace both drop the `-shell` suffix; the file follows the most-communicative term). It imports the v5 `homeModules.default` and sets `programs.noctalia.enable`, `package` (from the input, explicit), `settings` (the baseline below), and leaves `systemd.enable` off — the shell is spawned from niri, as today. `validateConfig` stays at its default `true`: the baseline TOML is validated at build time by the v5 binary's own schema engine, so schema drift on a future bump fails the build instead of the session. `libnotify` and `wl-clipboard` stay on the session PATH, with their comments re-grounded: v5 owns `org.freedesktop.Notifications` natively (default on), and its clipboard is a native wlr-data-control implementation — `wl-clipboard` remains solely for CLI consumers (gh-dash's `y`, scripts). v5's built-in polkit agent defaults to off and stays off (mate-polkit remains the agent); clipboard history is encrypted against the Secret Service gnome-keyring already provides on metis.

### The palette seam — the copy becomes a resolved symlink, explicit-trigger activated

v4's delivery (copy-into-place of a watched `colors.json`) is replaced by the constant-name custom palette, joining the exact per-target pattern `foot.ini`/`niri.kdl`/`gtk{3,4}.css` already use:

```
~/.config/noctalia/palettes/theme-menu.json → $stateDir/noctalia.json → $stateDir/current/noctalia.json
```

The entry-dir contract swaps the two per-polarity `colors-{dark,light}.json` artefacts for one: `noctalia.json` — a single per-family file (polarity-independent, unlike the other targets) containing `dark` and `light` objects, each carrying the 16 `m*` role keys of today's `renderColors` (same slot assignments, accent = base0D discipline) plus the v5-mandatory `terminal` block: `normal`/`bright` ANSI colours from the same base16→ANSI mapping the foot artefact uses, `foreground` = base05, `background` = base00, `cursor` = base05, `cursorText` = base00, `selectionFg` = base05, `selectionBg` = base02 — every slot commented, as the repo requires. The parser hard-falls-back to the builtin theme if `dark` or `dark.terminal` is absent, so the render helper emits both unconditionally. The old `colors-{dark,light}.json` artefacts, the copy-into-place block, and the seed's `colors.json` handling are deleted; the seed instead creates the `palettes/` dir and the `theme-menu.json` symlink (seed-if-absent, recreated like the GTK consumer links). v4's `~/.config/noctalia/colors.json` and `*.pre-609` backups become inert leftovers — harmless, noted for optional cleanup.

The family selection thereby lives in exactly one place — the conductor's `current` pointer; Noctalia holds a name (`theme-menu`) that never changes and a symlink it dereferences at resolve time. Nothing about the live selection is ever written into state Noctalia owns.

### Config baseline (minimal, declared)

`programs.noctalia.settings` declares only theming wiring, idle, and posture toggles — look, layout, and cosmetics stay runtime/GUI state in v5's overrides layer:

```toml
[shell]
setup_wizard_enabled = false          # the wizard's guided writes would persist theme
                                      # overrides into settings.toml — the exact
                                      # shadowing pathology the seam design avoids

[theme]
source = "custom"
custom_palette = "theme-menu"
mode = "<boot polarity>"              # from lib/palette-for.nix, boot default only

[theme.templates]
enable_builtin_templates = false      # ADR-044: Nix owns every external surface;
enable_community_templates = false    # explicit, not resting on empty-list defaults

[hooks]
started = "<polarity-reconcile script>"   # see below

[idle]
pre_action_fade_seconds = 0           # nobody is at the desk when these fire

[idle.behavior.lock]        # enabled, timeout ~600s, action "lock"
[idle.behavior.screen-off]  # enabled, timeout ~660s, action "screen_off"
[idle.behavior.suspend]     # enabled per-host, timeout ~1800s, action "command",
                            # command = the guard script (store path via getExe)
```

The suspend behaviour's `enabled` is a per-host flag flowing from `hostContext` — one line to disable at the #387 re-role (metis's planned future as a homelab server), on for Alcyone. Timeouts are placeholders finalised at implementation. Everything else (notification daemon on, polkit agent off, clipboard settings) rides v5 defaults undeclared.

### The `theme` CLI — one IPC call per switch

The repoint machinery is unchanged. The Noctalia delivery step becomes a single explicit trigger, exploiting the fact that *any* theme resolve re-reads the palette file through the symlink chain: if the **polarity** changed, `noctalia msg theme-mode-set <dark|light>` (which re-resolves, picking up any simultaneous family change for free); otherwise, `noctalia msg config-reload` (family-only change; mode untouched). One call, one palette transition (400 ms at the tag — `kTransitionDurationMs`, `theme_service.cpp`), both non-fatal outside a session like the existing `niri msg` step. The CLI discovers the socket by glob (`$XDG_RUNTIME_DIR/noctalia-*.sock`) rather than trusting `$WAYLAND_DISPLAY`: the client's environment-blind fallback guesses `wayland-0`, but metis's live session is `wayland-1`, so a bare `noctalia msg` from SSH would silently miss the shell — a regression v4's file-watch delivery didn't have, closed here in the CLI.

`theme-mode-set` necessarily persists a `theme.mode` override into v5's `settings.toml` — a duplicated copy of the polarity axis, which the one-place force forbids to go stale. The `[hooks] started` entry closes it: a two-line script reads the dconf color-scheme key (the polarity authority) and issues `theme-mode-set` accordingly on every shell start, so Noctalia always converges to dconf regardless of what its override recorded while the shell was down (compare-first via `theme-mode-get` to skip redundant persists; the shell's first paint may still show the stale echoed mode for a moment before the hook converges it — one visible flip, accepted). The family axis needs no such reconcile — the palette name is constant and the symlink is re-dereferenced at every start.

### Idle, sleep, caffeine

**Guard script** (a `writeShellApplication`, the suspend behaviour's `command`, with a `--dry-run` mode for probing): checks in order — (1) Noctalia's caffeine inhibitor visible in logind's inhibitor list (`who=noctalia, why=Caffeine`, the fingerprint source-verified at the tag) → stay awake; (2) established inbound SSH → stay awake; (3) detached agent workloads (pgrep pattern, tuned at implementation; linger is on, so SSH-teardown does not imply idle) → stay awake; else (4) `exec noctalia msg session lock-and-suspend` — Noctalia's own race-free path, which queues suspend on the compositor's `locked` event. The failure direction is "stays awake", correct for a remotely-used box. A skipped fire does not re-arm until input resets the idle timer — accepted, same direction.

**Caffeine contract (operator call, 2026-07-25 — gate suspend only, not lock/screen-off):** the bar's native caffeine toggle guarantees *no suspend* — the guard reads its logind inhibitor, turning upstream's dead-end acquisition into our readable state. At beta.4 caffeine does **not** suppress the lock and screen-off behaviours (upstream bug: `IdleManager` consults only D-Bus screensaver inhibits, and the Wayland `zwp_idle_inhibitor` path — the one compositors honour — is unreachable when logind is present); the screen still locks and blanks under caffeine, and media playback is separately covered by the D-Bus inhibit path v5 honours natively. The bug is to be reported upstream as part of this work; when fixed, the contract widens to full caffeine semantics with zero wiring change here, and the guard's caffeine check remains as harmless defence-in-depth. Coupled migration trigger: on every Noctalia bump, re-probe caffeine semantics (does lock still fire under caffeine?) and the inhibitor fingerprint (can the guard still read it?) together.

**Lock-before-any-sleep:** `services.systemd-lock-handler.enable = true` (in the pinned nixpkgs) holds a genuine logind sleep delay-inhibitor and bridges to a user-level `sleep.target`; a oneshot user unit ordered before it runs `noctalia msg session lock` with a short settle (no lock-state query exists in v5's IPC), so *every* suspend path — idle-fired, `systemctl suspend`, future power-key — is preceded by an engaged lock while sleep is held. A hand-rolled system-level `Before=sleep.target` unit is explicitly rejected (asynchronous, no session context — the race it leaves is the one this restores the guarantee against). If the shell is dead, nothing locks — but nothing idle-suspends either; recorded as the residual, not solved. Wake-on-LAN is out of scope: metis's NIC capability is probed and recorded during validation, enablement waits on the future always-on LAN peer (follow-up issue); until then wake-from-suspend requires physical presence — stated, not implied away.

### Mechanical rewiring

`home/nixos/niri.nix`: `spawn-at-startup` → the v5 binary via `getExe`; `Mod+Space` → `["noctalia" "msg" "panel-toggle" "launcher"]`. `home/nixos/set-font.nix`: `restart_shell`/`hint_shell` re-target the `noctalia` process (the quickshell pkill is dead); whether v5 still caches fonts at process start is a validation probe, and the helper survives either answer. The v4 runtime state (`settings.json`, GUI look) has no importer — the operator reconstructs the shell's look once in the v5 control centre, where it lives on as legitimate runtime state; the wizard stays disabled so day-one writes are deliberate.

### How the forces are met

Nix remains sole theming authority (templates off, conductor renders every surface); each selection lives in one place (family = pointer with a constant-name dereference; polarity = dconf with a started-hook reconcile over the persisted echo); runtime selection survives rebuilds (seed-if-absent untouched); a fresh provision boots from declared `config.toml` with the wizard suppressed; the baseline is minimal (theming, idle, posture — nothing cosmetic); every repaint is an explicit trigger (`theme-mode-set`/`config-reload`, no watch assumed); the upstream-facing seam count is four (palette schema, the `[theme]` keys, the IPC verbs, the override semantics) with migration triggers recorded; metis validates each claim at runtime before Alcyone inherits; and both stance changes are named above with their guards and residuals stated.

## De-risk evidence

All upstream claims were verified by reading source at the release tag — `noctalia-dev/noctalia` @ `v5.0.0-beta.4` = commit `4c2dcd0995f9c570c0ced95561bf5e4685e2ad1b` — via shallow clones (a research pass, then two independent adversarial review passes, 2026-07-25). Live-host facts were probed read-only on metis the same day. Source-read is not runtime: every behavioural claim below still gates on the on-metis probe plan at the end of this section.

**Verified at source (tag, with locations):**

- v4's `~/.config/noctalia/colors.json` has no v5 read path (repo-wide; the only `colors.json` is the pywal cache for the Firefox theme helper). Chrome colours resolve in-process from `[theme]` (`src/theme/theme_service.cpp` `resolveAndSet`, ~457–550), which re-reads the custom palette file from disk on every resolve through any symlink chain (plain `exists` + ifstream, ~461–466). Custom palettes live at `~/.config/noctalia/palettes/<name>.json`; the parser requires `dark` and `dark.terminal` — and a `light` object present without its own `terminal` fails the whole parse too — falling back to the builtin theme with only a log warning (`custom_palettes.cpp`, `theme_service.cpp` ~99–198); the render helper therefore emits `terminal` for both modes unconditionally.
- Palette JSON is never hot-reloaded: the inotify machinery watches only `*.toml` (config dir, includes, symlink targets, state-dir `settings.toml`) (`config_service.cpp` ~867–922, ~1097–1170). `config-reload` is unconditional — reload + re-resolve with no changed-check (`forceReload`, ~875).
- Theme IPC writes persist unconditionally into the state-dir `settings.toml` overrides, which win over `config.toml` with no pruning outside GUI reset paths (`config_overrides.cpp` ~884–960). This is the finding that killed the catalogue-as-`customPalettes` alternative (§Rationale): any design letting Noctalia persist the *family* selection duplicates live state into a file Nix cannot reach.
- Config layering (read-only `config.toml` + `settings.toml` overrides + `state.toml`) is by design symlink-aware (`config_service.cpp` ~548–560, ~1114–1141); `validateConfig` runs the binary's own `config validate` at build time; config migrations are intra-v5 only — no v4 `settings.json` importer exists (repo-wide grep).
- IPC grammar is `noctalia msg <verb>` over `$XDG_RUNTIME_DIR/noctalia-$WAYLAND_DISPLAY.sock`; with `WAYLAND_DISPLAY` unset the client guesses `wayland-0`, with 2 s connect/send/recv timeouts (`ipc_client.cpp` ~24–28) — and metis's live session is `wayland-1` (probed), so an environment-blind invocation silently misses the shell; the CLI's socket-glob discovery (§Design) exists for exactly this, and probe V5 validates it. Verbs used by this design: `theme-mode-set`, `theme-mode-get` (registered at `theme_service.cpp` 670–676 — the started-hook's compare-first read), `config-reload`, `panel-toggle`, `session lock`, `session lock-and-suspend`, `caffeine-{enable,disable,toggle}` (no caffeine status verb exists — `idle_inhibitor.cpp` 175–224).
- Idle: behaviours fire from compositor ext-idle-notify timers; the only suppression consulted at fire time is the D-Bus screensaver inhibit count (`idle_manager.cpp` 334). Caffeine acquires `Inhibit("idle", "noctalia", "Caffeine", "block")` from logind and *destroys* its Wayland `zwp_idle_inhibitor_v1` surfaces whenever logind granted the fd (`idle_inhibitor.cpp` `syncInhibitor` ~183–197, `logind_service.cpp` 148–151) — so caffeine does not gate idle behaviours on systemd systems (the upstream bug this work reports), while its logind fingerprint is stable, readable state for the guard script. Caffeine's enabled flag is never persisted — session-scoped by construction.
- Sleep: no sleep delay-inhibitor anywhere in the tree (the idle-class caffeine call is the only `Inhibit`); `PrepareForSleep` does resume housekeeping only. The logind session `Lock` signal *is* honoured (`application_ui.cpp` ~337–358), and Noctalia-initiated `lock-and-suspend` queues suspend until the compositor's `locked` event *and* lock-surface readiness (`lockThenSuspendDetached` → `runAfterSessionLocked`; the 3 s timer is armed *inside* `handleLocked` and covers slow surface rendering only — if the compositor never emits `locked`, the pending suspend never fires and the box stays awake, the fail-awake direction) — the race-free path the guard delegates to. `SetLockedHint` is never called, so `LockedHint` is unusable as a validation signal. The lockscreen uses ext-session-lock-v1, whose protocol obliges the *compositor* to blank outputs before lock-surface content shows — a niri-side guarantee, not a noctalia-source claim. PAM service is hardcoded `login`; `NOCTALIA_PAM_SERVICE` is gone.
- Packaging: flake exposes `homeModules.default` + per-system packages (sole input nixpkgs, no cache offered); the HM module namespace is `programs.noctalia`, installs the package only when non-null, writes `config.toml` read-only when `settings` is set; `meta.mainProgram` is `noctalia`; the binary wraps `git` onto PATH. PipeWire/WirePlumber are link-time dependencies (`nix/package.nix`); the running-daemon requirement is upstream-README-stated, not source-established — both are active on metis regardless.
- Startup ordering: the IPC socket is initialised *before* the startup-hooks phase (`application.cpp` ~229–234), and hooks run via `/bin/sh -lc` on a detached thread (`process.cpp` ~789–793) — the started-hook's `noctalia msg` call lands in the socket backlog and is served; no chicken-and-egg. `theme-mode-set` to an unchanged mode persists idempotently and re-resolves without animating (`startTransition` short-circuits on an equal palette, `theme_service.cpp` ~566).
- Every config key in §Design's TOML sketch exists under its exact name in the v5 schema (`config_schema.cpp`: `shell.setup_wizard_enabled` 1453; `theme.source`/`custom_palette`/`mode` 1149–1154; both template toggles 1107–1109; `hooks.started`; `idle.pre_action_fade_seconds` 870; `[idle.behavior.<name>]` with `enabled`/`timeout`/`action`/`command` 830 ff). Caveat: the schema does **not** validate the `action` string — a typo silently falls through to command mode, and `validateConfig` will not catch it.
- `services.systemd-lock-handler` exists in the pinned nixpkgs (`nixos/modules/services/system/systemd-lock-handler.nix`) with the user-level `lock`/`unlock`/`sleep.target` bridge §Design relies on.

**Verified live on metis (read-only, 2026-07-25):**

- gnome-keyring owns `org.freedesktop.secrets` on the session bus (encrypted clipboard history can persist); `pipewire` and `wireplumber` units active.
- `eno1` (Intel I219, e1000e): PME armed (`/proc/acpi/wakeup` GLAN enabled, device wakeup enabled); actual WoL mode and BIOS S3 setting unprobed (root ethtool + firmware — recorded, not assumed). Magic packets are L2 — tailscale cannot deliver them; wake needs a LAN peer (future, out of scope).
- logind: `HandlePowerKey=poweroff` (masked in-session by niri's inhibitor; the "power key suspends" path does not currently exist — side-finding for a follow-up), `IdleAction=ignore` (logind is not driving idle; Noctalia is).
- v4 runtime state: all six `activeTemplates` disabled, `useWallpaperColors` false, idle disabled, customised bar layout in `settings.json` — confirming the reconstruction burden and that no v4 theming writer will collide during cutover.
- This terminal holds the niri socket: `niri msg action screenshot-screen` + direct image reading are available as verification instruments.

**Adversarial review outcomes (three passes, 2026-07-25; findings absorbed into this section, and the full review texts frozen as research notes — [palette seam](../research/noctalia-v5-palette-seam-review.md), [idle/sleep](../research/noctalia-v5-idle-sleep-review.md), [De-risk audit](../research/noctalia-v5-derisk-audit.md)):**

1. *Palette seam*: the initially-proposed catalogue-as-`customPalettes` + IPC-name-switching design was **rejected** on the `settings.toml` persistence finding (family selection duplicated into GUI-owned state; shell-down switches produce durable split-brain; the populated GUI picker becomes an attractive nuisance). The adopted constant-name symlink design was identified by that review as dominating both it and a mutable-file port.
2. *Idle/sleep*: caffeine-as-guard-input adopted after the caffeine-doesn't-gate finding; `systemd-lock-handler` identified as the delay-inhibitor mechanism (present in the pinned nixpkgs); WoL found load-bearing-but-unproven and descoped to a follow-up with the guard promoted to primary mitigation; `LockedHint` disqualified as a probe.
3. *This section itself*: a third pass audited the De-risk claims against a fresh source read — every load-bearing claim reproduced; its corrections (the `lock-and-suspend` fallback semantics, the never-`locked` residual, the PipeWire wording, the blanking attribution, two line-number drifts) and its found gaps (the C0 build gate, V0, the C2/started-hook contradiction, the impossible original V6, the SSH socket-guess miss) are incorporated below and in §Design.

**Still unverified — the on-metis probe plan (the validation gate for this design):**

*Ordering and hazards:* C0 and V0 run first. C2 is observable only on the very first v5 start (a state-dir wipe is needed to repeat it). V3 kills the live shell mid-session. S2, S4, and S5 each end locked or suspended and need a body at the keyboard — run them last, S4 before S5; S3's real-fire step and S4 each need a temporary config edit.

*Palette seam:* **V0** locate where the niri-spawned shell's stderr/journal lands (V1 and V6's log criteria depend on it). **V1** shell starts on the `theme-menu` palette through the full symlink chain (no builtin-fallback warning in the log). **V2** `theme <family>` triggers exactly one resolve — with `NOCTALIA_PROFILE=1`, one `resolveAndSet` timer line per switch and before/after screenshots that differ; a repoint *without* the IPC call triggers zero resolves and no repaint (confirms no-watch). **V3** shell-down switch: kill the shell, `theme <family2>`, respawn → comes up on family2; `settings.toml` never contains `source`/`custom_palette` keys. **V4** polarity: `theme light` → only a `mode` key appears in `settings.toml`; flip polarity while the shell is down, start it → the started-hook converges Noctalia to dconf. **V5** the CLI's socket-glob discovery delivers the repaint from an SSH shell with `WAYLAND_DISPLAY` unset (the bare client fallback guesses `wayland-0` and must not be relied on — metis's socket is `noctalia-wayland-1.sock`); with no shell up, failure is clean and non-fatal. **V6** with the state symlink's target temporarily renamed, `config-reload` → builtin fallback + log warning (the recognisable failure signature); restore and re-reload (the original point-at-a-missing-name formulation is impossible — `color-scheme-set` validates palette existence and refuses). **V7** watch bar/OSD during `config-reload` for disruptive flicker.

*Idle/sleep/caffeine:* **S1** `sudo ethtool eno1` → `Supports Wake-on` includes `g` (capability recorded for the WoL follow-up; enablement out of scope). **S2** `loginctl lock-session` engages the lockscreen (journal + screenshot; not `LockedHint`). **S3** guard `--dry-run`: caffeine on → skip; live SSH → skip; detached agent → skip; clean → suspend branch selected; plus one real idle fire at a short timeout with the guard in dry-run writing a marker file — proving the `action = "command"` spawn path (`/bin/sh -lc`, detached thread) runs the store-path guard as configured. **S4** caffeine-semantics probe: short lock timeout + `caffeine-enable`, hands off → lock fires, confirming the upstream bug on hardware (the reproduction the upstream report will cite); also confirms caffeine state is session-scoped across a shell restart. **S5** *(operator-assisted, the one real suspend)*: `systemctl suspend` with an SSH session open and monitor on → on resume the lock surface is present (screenshot), and `noctalia-lock-on-sleep`'s completion timestamp strictly precedes the kernel's `PM: suspend entry` in the journal, with the user `sleep.target` shown activated (proving the systemd-lock-handler bridge, not coincidence) — lock-before-sleep proven, not asserted.

*Cutover hygiene:* **C0** the flake input's package builds against the repo's nixpkgs pin, *before* the cutover branch is cut — **passed on metis 2026-07-25**: eval reproduces (drv `/nix/store/xxk0x2izdbzcw30vnjdkyq6dchaabsk5-noctalia-5.0.0.drv`) and the full compile succeeded (output `q7vdqqq…-noctalia-5.0.0`, `bin/noctalia` present). The only probe already discharged; it re-runs trivially at any future pin move. **C1** the build-time `validateConfig` run passes in the Nix sandbox. **C2** first v5 start with the wizard suppressed writes no overrides beyond the started-hook's own `theme.mode` echo, if any (first-start-only; with compare-first the hook writes nothing when dconf already matches the boot mode). **C3** clipboard history survives a shell restart (Secret Service path exercised). **C4** `notify-send` renders (daemon ownership). **C5** the niri `Mod+Space` bind toggles the launcher via the new IPC. **C6** font cache: `set-font` switch → screenshot the bar; shell restart → screenshot again; identical renders = no process-start cache (calibrates `set-font`'s hint/restart helper).

## Drawbacks

**We are jumping before our own recorded trigger.** ADR-036 deferred v5 to "when v5 ships a *stable* tag with NixOS-module and feature parity". beta.4 is not that; the actual driver is Alcyone's timeline. The honest alternative is to wait for v5.0.0 stable and bootstrap Alcyone on v4 (or bootstrap it later) — rejected by the operator's sequencing call, but it is the cleanest argument against this note: we trade a frozen-but-stable shell for a beta whose `main` moves daily, and take on a re-probe burden at every future bump.

**The design leans on one-tag internals.** The load-bearing verifications — the overrides file's no-pruning persistence, the hook-vs-socket startup ordering, the caffeine inhibitor fingerprint, the palette parser's failure mode, the IPC verb set — are all facts about commit `4c2dcd0`, not commitments upstream has made. Any of them can move silently between beta.4 and stable. The seam count is minimised and the migration triggers are recorded, but a beta re-integration is structurally a bet that these internals hold long enough to be worth re-verifying per bump.

**We deepen the bespoke compensation layer.** The guard script, the started-hook polarity reconcile, the CLI's socket-glob discovery, and the lock-on-sleep unit each exist to compensate for an upstream gap (caffeine not gating idle; no portal polarity read; an environment-blind IPC client; no sleep delay-inhibitor). That is four more moving parts that are ours — to maintain, to re-validate, and eventually to unwind as upstream fixes land. The alternative posture — run v5 vanilla and accept the degraded semantics until stable — is simpler and was declined in favour of keeping ADR-044's guarantees intact through the migration.

**Single-cutover on the only desktop.** There is no pilot host; a failed cutover degrades the operator's daily driver. Generation rollback bounds the damage (v4 is one `nh os switch` away), but the v4 runtime state adds asymmetry: rolling forward again later means reconstructing the GUI look a second time, since nothing imports it.

**The suspend stance ships with a known residual.** Even guarded, enabling suspend on a remotely-used box before Wake-on-LAN exists chooses an outage class: a guard miss (an agent pattern not matched, an SSH check raced) means a walk to the desk. Validate-then-disable-until-Alcyone was the conservative alternative; the operator chose live validation with the guard and caffeine switch as the mitigations, and the WoL follow-up as the eventual fix — but while that follow-up is open, this note's stance is strictly less reachable than today's never-suspends metis.

**The overrides layer remains a standing foot-gun.** v5's `settings.toml` is GUI-writable state that beats our declared config wherever it holds a key, and Nix cannot reach it. The design keeps the *family* selection out of it entirely and reconciles the one echoed key (`theme.mode`), but any future GUI touch of the theme picker re-opens a shadowing channel that only convention ("the conductor owns the selection") and a documented recovery close — the same class of residual ADR-044 accepted for v4's pickers, inherited here with one more layer that can hold state.

## Cost

Three standing prices of the chosen direction, distinct from the reasons-against above:

- **A re-verification ritual on every Noctalia bump.** The coupled probe pair (does caffeine now gate idle behaviours? is the logind inhibitor fingerprint still readable?) plus a re-check of the four seam facts (palette schema, `[theme]` keys, the IPC verbs, override semantics) is part of the bump procedure, not an optional extra — the price of building on one-tag internals. Cheap per bump (we pin release tags, so bumps are deliberate), but never free, and it lasts until upstream stabilises the seams or fixes the caffeine bug.
- **A local C++ build on every bump.** No binary cache exists for v5; each pin move compiles the shell on the host (meson/ninja, gcc C++23 — materially lighter than v4's Qt closure, but minutes, not seconds, per host per bump).
- **GUI look reconstruction per fresh provision.** The minimal-baseline posture deliberately leaves bar layout, launcher preferences, and cosmetics as runtime state in v5's overrides layer — so every fresh provision (and this cutover itself) includes a one-time manual pass in the control centre. This is the same runtime-state price ADR-036 accepted, re-signed here knowingly rather than inherited by default.

## Rationale & alternatives

**Migration timing — now, at beta.4, rather than at v5 stable.** Waiting honours ADR-036's recorded trigger and avoids every beta cost above; it loses to sequencing: Alcyone (#631) is meant to be v5 from first boot, and the choice is between validating the rewrite on metis — attended, rollback-capable, operator at the desk — or debugging it mid-bring-up on unproven hardware. Bootstrapping Alcyone on v4 was the third option, and the worst: it doubles the migration (v4 onto new hardware, then v5 across two hosts) onto a line frozen into maintenance. metis-first at the current tag is the smallest total risk, and the beta exposure is bounded by pinning the release tag and recording the per-bump ritual (§Cost).

**The palette seam — three candidates, adjudicated adversarially (2026-07-25).** (1) *Catalogue-as-`customPalettes` + IPC name-switching*: declare every family as a named palette, switch by `color-scheme-set custom <family>`. Rejected — v5 persists every theme IPC write into its GUI-owned overrides file with no pruning, so the family selection would be duplicated into state Nix cannot reach: the boot-default guarantee dies after the first switch, a shell-down switch leaves durable split-brain, and the populated GUI picker becomes a half-working attractive nuisance. This recreates the pathology ADR-044 exists to kill, one layer down — the finding that minted the dereference-not-copy force. (2) *Conservative mutable-file port*: one palette file overwritten by the CLI + `config-reload`, closest to the v4 shape. Sound on the family axis, but retains runtime file mutation and the copy machinery v4 only needed because its watcher couldn't see symlink swaps. (3) *Constant-name symlink chain* (**chosen**): v5 has no palette watcher at all, so an explicit trigger is mandatory regardless — which makes symlink delivery viable again and B's copy step pure overhead. The palette takes `colors.json`'s old slot in the resolved-symlink set, the family selection stays solely in the conductor's pointer, Noctalia's overrides never learn a family name, and the seam count is the smallest of the three. B is the fallback if a v5 change ever breaks symlinked palette reads (V1 guards this).

**Config posture — minimal declared baseline over both extremes.** *Full declarative translation* (bar layout, launcher, cosmetics in TOML) maximises reproducibility but pins every cosmetic tweak behind a rebuild and abandons the GUI-managed ergonomics the operator explicitly kept in ADR-036 — and the overrides layer would shadow it anyway at first GUI touch, making the pin partly illusory. *v4's enable+package-only posture* leaves theming wiring, idle, and the wizard to runtime chance — unreproducible exactly where ADR-044 demands reproducibility. The minimal baseline declares what must be true on a fresh provision (theming wiring, idle, posture toggles) and leaves what may vary (look) to the layer v5 built for it. This is the operator's call of 2026-07-25, and it is also what v5's config layering is *for*.

**Suspend mitigation — the guard script over its rivals.** *Native caffeine alone*: disqualified — it does not gate idle behaviours on systemd systems (the upstream bug). *An inhibitor daemon* (hold a sleep block-inhibitor while SSH lives): a standing service to build and maintain, produces failed-suspend noise each idle cycle, and still misses detached agents. *A bare generous timeout*: not a mitigation, a hope. The guard script is declarative (a store path in config), daemon-less, covers detached agents and the caffeine switch in one place, delegates the actual suspend to Noctalia's own locked-event-gated path, and fails in the correct direction (awake). *Validate-then-disable on metis* was the conservative stance alternative; the operator chose live suspend with the guard, and the per-host flag keeps the #387 exit one line away.

**Before-sleep hook — `systemd-lock-handler` over a hand-rolled unit.** A system-level `Before=sleep.target` unit firing `loginctl lock-session` is asynchronous — it returns on signal emission, racing the freeze with no session context. The nixpkgs `systemd-lock-handler` holds a genuine logind sleep delay-inhibitor and bridges to user-level targets, so the lock unit provably completes before sleep proceeds; S5's journal-ordering probe turns "provably" from design intent into recorded fact.

**Doing nothing** leaves metis on a shell frozen into maintenance, Alcyone with no good bootstrap target (a dead line, or an unvalidated beta mid-bring-up), ADR-044's Noctalia seam wired to a mechanism upstream has already deleted, and the lock-before-sleep and caffeine gaps unaddressed. The migration is coming regardless; this note only chooses *when* and *how much of it we control*.

## Prior art

**In-repo.** [ADR-044](../decisions/ADR-044-linux-runtime-theme-menu.md) and the [colour-conductor design note](./colour-conductor.md) are the direct ancestors: per-family store artefacts, the resolved-symlink pattern, explicit reload triggers, and the seed-if-absent rule — this note extends that mechanism by one target rather than inventing one. The v4 copy-into-place saga is the formative lesson: a source-read conclusion about Noctalia's watchers was falsified by on-metis runtime verification (#609, ADR-044 §History), which is why the dereference-not-copy force exists and why every behavioural claim here gates on probes. The per-app reload evidence and pty-discovery groundwork live in [`docs/research/omarchy-theme-switching.md`](../research/omarchy-theme-switching.md) and its validation companion. The retired swayidle stack ([`docs/desktop/screen-lock.md`](../desktop/screen-lock.md), [`power-session.md`](../desktop/power-session.md)) is the repo's own precedent for timeout-fired scripts and before-sleep lock hooks — the guard script and lock-on-sleep unit are that pattern re-hosted.

**Upstream and community.** v5's intended theming model — wallpaper-derived M3 plus a matugen-compatible template engine pushing colour *outward* to apps — is the community norm for Noctalia users; this design deliberately inverts it (Nix pushes colour *in*; templates off) per ADR-044, using only the custom-palette read path. The HM module's `customPalettes` option is upstream's declared-palette route; bypassing it is a reviewed decision (§Rationale), not an oversight. `systemd-lock-handler` is the established xss-lock lineage (logind delay-inhibitor + lock bridge) ported to user-level systemd targets — a maintained nixpkgs module, not bespoke machinery.

## Unresolved questions

Expected to resolve **during implementation**: final timeout values for the three idle behaviours; the guard's detached-agent match pattern (start conservative, tune on evidence); the `hostContext` key shape for the per-host suspend flag; exact file/module homes per the taxonomy.

Expected to resolve **during validation**: C0's compile outcome (eval already passes; result folds into §De-risk before acceptance); V0's answer (where the spawned shell's stderr lands), which calibrates several probe instruments; whether the started-hook's `/bin/sh -lc` environment carries the session bus for `dconf read` (V4 covers it; fallback is deriving polarity from the conductor's own state symlink instead of dconf); C6's font-cache answer, which calibrates `set-font`.

**Out of our control:** the upstream caffeine bug report's fate — the coupled per-bump probe pair stands until it lands.

**Explicitly out of scope:** WoL enablement (follow-up issue when the always-on LAN peer exists; BIOS check rides with it); power-key handling (`HandlePowerKey=poweroff` side-finding — follow-up); the E2 Stylix literal removal (ADR-036's deferred full-removal refinement, #390); the #387 re-role beyond keeping its one-line suspend exit; all Alcyone-specific work (#631 inherits the proven result).

**Resolved at acceptance (2026-07-25):** the three adversarial review texts are frozen as `docs/research/noctalia-v5-*.md` (linked from §De-risk), per the frozen-research-evidence rung of the design loop.
