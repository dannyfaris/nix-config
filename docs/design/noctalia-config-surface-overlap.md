# Noctalia config-surface overlap — a decided posture for every declared key

**Status:** Proposed — design note (`docs/design/`). **Built, deployed, and on-metal verified on both desktop hosts** — alnair 2026-08-18 (enforcement pass against a real shadow, gate iii), alcyone 2026-08-20 (clean pass). Decision-state advances to Accepted with the successor ADR (operator gate). #866 (reframed at class level, [the comment](https://github.com/dannyfaris/nix-config/issues/866#issuecomment-5313312707)) · #877 (the template convention this generalises) · relates to [ADR-048](../decisions/ADR-048-noctalia-theming-delegation.md) (the delegation whose boundary this maps) and [ADR-032](../decisions/ADR-032-proportionate-enforcement-and-rationale.md) (the enforcement-sizing rule the guards follow).

## Summary

Noctalia's config surface has two legitimate writers — the Nix-declared read-only `config.toml` and the GUI's `settings.toml` sidecar, which loads last and wins per key — and this repo has never mapped where they overlap. This note assigns every key we declare one of three **postures**: **seed** by default (Nix states the baseline; the operator tunes live in the GUI, and the tuned value legitimately wins), **authoritative** by exception (`[theme.templates]` whole-table plus any declared leaf whose value is a store path — GUI divergence on these is a fault, reverted at session start by a pre-spawn reconcile wrapped around the shell's launch), and **delegated** unchanged (nothing declared; the GUI owns it outright, the ADR-048 posture). One repo script — run by an agent on demand and as a per-bump ritual step, never a timer — computes the declared-vs-GUI-writable intersection from the pinned source and reports sidecar divergence as mechanical facts: forbidden-key hits, redundant shadows, and diffs left to operator judgment. CLAUDE.md and workflow.md gain the agent-facing pointers in the same change.

## Motivation

The problem surfaced as #866: a GUI tick wrote a complete `builtin_ids` array into the sidecar, wholesale-replacing the reviewed template whitelist and re-enabling the deliberately disqualified `starship` template — silently, because nothing in the UI or logs signals an override is in play (`template` appears zero times in `noctalia.log`). Working the fix (#877) showed the channel is not template-specific: the settings registry carries **354 `makeEntry` registration sites** at the pinned `v5.0.0-beta.8` (269 paths literal-extractable plus dynamic per-instance and per-hook idioms; the measured breakdown is §De-risk gate v), and `[idle]` is among them with a different failure mode — editing *any* idle row writes the **entire** behaviors collection into the sidecar, every leaf populated, freezing the declared suspend `command` (a store path, `lib.getExe idleGuard`) at its then-current value. A later rebuild moves the store path; the sidecar keeps the stale one; GC eventually breaks it. Divergence-as-decay rather than divergence-as-preference.

Underneath both incidents is one unmapped fact: for each key this repo declares, whether the GUI can also write it is an *accident of upstream's registry at the pin* — never decided, never re-checked across bumps. The repo's own test — "was this decided" — has not been applied to the boundary itself.

The operator's ruling on how the machine should feel (stage 1–3 dialogue, 2026-08-17) sets the central force: the GUI must remain a legitimate live-tuning surface for declared baselines — "I back myself to keep track of what's changed, and an agent should be able to periodically review active vs declared settings if I need it to." Locking every declared key was explicitly considered and rejected.

Forces any design must satisfy:

- **F1 — the boundary is decided, not accidental.** Every declared key's GUI-overridability is a recorded choice ("everything here is on purpose").
- **F2 — live tuning stays legitimate.** Declared baselines are tunable in the GUI without the machine fighting back (operator ruling; rules out lock-everything).
- **F3 — the trust surface is not GUI-mutable in effect.** Template enablement admits scripts onto the host; a stray tick must not durably change which scripts may run (#877's ratified convention, held by mechanism rather than diligence).
- **F4 — divergence is never silent-and-invisible.** Prevented where forbidden; discoverable on demand where allowed. Set ≠ enforced (#303) applied to the two-writer seam.
- **F5 — enforcement is proportionate** (ADR-032): the lightest mechanism per severity; no push notifications or timers nagging about legitimate tuning.
- **F6 — single-sourced authority.** The authoritative-key list exists in exactly one place, consumed by both guard and audit.
- **F7 — upstream as-is.** No dependence on upstream changes; the parked upstream ask (Draft B, #866) is informed by this design, not load-bearing for it (operator ruling).
- **F8 — bump-proof.** The GUI-writable registry is a fact of the pinned tag; the classification is re-derivable mechanically at every bump, so a bump that makes a declared key newly GUI-reachable surfaces as a diff, not folklore.

## Design

### The three postures

| Posture                       | Meaning                                                                                                     | Operator experience                                                                                                                                                                          | Assignment                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Seed** (default)            | Nix states the baseline; the GUI legitimately overrides it. A sidecar value winning is working-as-intended. | Change it in the control centre; it sticks. The flake value goes inert on that host until the override is cleared — a cost the operator has explicitly accepted and the audit makes visible. | Every declared key not on the exception list.                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Authoritative** (exception) | Declared is the only legitimate value. A sidecar entry is a fault, whatever its content.                    | The GUI will accept the change, and the reconcile reverts it at next shell start; the audit flags it immediately if run sooner. Changing these for real means editing the flake.             | `[theme.templates]` — the whole table (all four keys: `enable_builtin_templates`, `builtin_ids`, `enable_community_templates`, `community_ids`); plus any declared leaf whose value is a store path — today exactly two, `idle.behavior.suspend.command` and `hooks.colors_changed` (the latter admitted by stage-6 review finding 1: the hooks family is GUI-writable through a dynamic per-HookKind registration the literal extraction cannot see). |
| **Delegated**                 | Nothing declared; the GUI owns the key family outright.                                                     | Click freely; git remembers nothing (ADR-048's recorded trade).                                                                                                                              | Theme selection, bar layout, launcher preferences, cosmetics — unchanged.                                                                                                                                                                                                                                                                                                                                                                              |

The exception list is a whitelist of two entries, not a per-key matrix: whitelist-over-blanket applied to the boundary. The store-path rule is stated as a *predicate*, not an enumeration — any future declared leaf carrying a store path (a `command`, a hook path) is authoritative by construction, because no one tunes a store path in a GUI; its presence in the sidecar is only ever rot.

Declaring a key now carries sharpened meaning: seed keys say "this baseline matters; tune it if you like", authoritative keys say "this is mechanism; the flake is the only writer". A key the operator finds themselves tuning permanently is a candidate for *undeclaring* (delegation), not for a new posture.

### The audit script

One script in `scripts/` (working name `noctalia-config-audit.sh`), runnable by an agent on demand and named as a step in the `docs/desktop/noctalia.md` §Sharp edges per-bump ritual. No timer, no service (F5). Three inputs, all read-only:

1. **The declared config** — read from the host's rendered `~/.config/noctalia/config.toml` (ground truth for what Nix actually shipped, no eval needed).
2. **The sidecar** — `~/.local/state/noctalia/settings.toml`, read-only. The script never writes under `~/.local/state/noctalia/` — the audit reports; only the reconcile (declared mechanism, below) and the operator mutate.
3. **The GUI-writable registry** — extracted from the pinned Noctalia source (the store path of the flake input's `src`) by pattern-matching the settings sources' setting-path literals: **268 literal paths at beta.8** (segments exclude `.` — allowing it pulled in ~38 value/i18n option-pairs that are not setting paths at all; stage-6 finding 2), **plus known dynamically-registered families appended explicitly** — `hooks`, registered per-HookKind in a runtime loop, invisible to any literal pattern and declared-relevant (stage-6 finding 1) — for a shipped set of 269. The residue is the per-instance helper-lambda idiom (`bar.*`, `wallpaper.monitor.*`), none declared by this repo. The extractor carries a coverage line (matched vs. 354 total `makeEntry` sites) so the gaps are reported rather than silent, and the extraction failing to match anything is a loud `fail`, not a silent pass — per F8, breakage of the check is itself a signal. Grep-tier against upstream source layout, per ADR-032 the proportionate rung.

Output is a short report of **mechanical facts only** — no intent-guessing:

- **Forbidden:** any sidecar entry under an authoritative key. Rendered with the exact recovery (the #877 procedure) — or a note that the next shell start reconciles it.
- **Redundant:** sidecar leaves equal to the declared value. Safe to clear, and worth clearing — they silently block future flake changes to that key.
- **Diverged:** sidecar leaves differing from declared, listed as diffs for operator judgment. The audit does not classify tuned-vs-dragged — that distinction is not machine-decidable and pretending otherwise would be false confidence. The one heuristic it may annotate: a diverged leaf that is a dangling store path is certainly rot, not tuning.
- **Registry drift** (per-bump mode): declared keys whose GUI-reachability changed since the recorded baseline — bucket 3's "accidentally safe" keys becoming reachable is exactly the drift F8 exists to catch.

### The reconcile

**Pre-spawn**, not in-session (ruling 2-bis, 2026-08-17, amending fork 2's *slot* on stage-4 evidence — the bounded-at-startup cadence ruling itself stands): a Nix-declared wrapper around the `noctalia` launch in niri's `spawn-at-startup` runs the check-and-repair *before* the process exists. The originally proposed `hooks.started` slot is disqualified by three independent stage-4 findings: (1) the startup echo-drain hazard — `checkReload()` never runs until the main loop polls, which is *after* `hooks.started` fires, so every startup-window inotify event lands in one first drain, and the own-write echo filter (`config_service.cpp:915-918`, aggregate-per-drain, source-confirmed) discards that drain wholesale if any own-write flag is pending — the hook's external edit can be silently swallowed; (2) editing a file the running process watches and rewrites; (3) a sidecar parse failure wipes *all* overrides (`loadOverridesFromFile` resets to an empty table on `toml::parse_error`, source-confirmed), so a botched in-session write would destroy the operator's theme pick and every runtime preference. Pre-spawn sidesteps the entire class by construction: `ConfigService`'s constructor reads the file before the inotify watch exists — a file corrected before spawn is simply the starting state, with no reload, no race, and no echo filter in the path.

Behaviour: if the sidecar contains any authoritative key, back it up in place (non-`.toml` suffix, the #877 pattern), remove those keys into a temp file, run a **structural post-check** — exactly the target regions differ from the backup, nothing else — and only then move the result into place; on any post-check failure, leave the original untouched and flag. Every outcome is logged to a state-dir log (no silent success, #303) — self-logging is mandatory in any slot: Noctalia's hook executor redirects hook stdio to `/dev/null` (source-confirmed), and a pre-spawn wrapper has no other reporting channel either. The standing "agents never write under `~/.local/state/noctalia/`" rule is not violated: this is declared mechanism executing as the operator's session — the same class as the repaint hook — not an agent mutating runtime state ad hoc.

Mechanism ladder, as resolved by stage 4: **(a) IPC-dedup is dead** — the dispatch table (~105 verbs) was enumerated at the pin; every verb is a scoped, single-purpose setter, and no general settings-write/override-clear verb exists. **(b) Surgical TOML edit** is the chosen rung, viable only with the structural post-check: gate (ii) showed awk-tier surgery handles the writer's canonical output but fails *silently* on legal hand-edited shapes (a trailing comment on a table-header line caused deletion of an entire unrelated table while still passing a TOML parse check — parse validity is structurally blind to under-deletion, so the post-check, not the parser, is the safety gate). **(c) Flag-only** remains the honest fallback if (b)'s post-check proves unimplementable at the awk tier.

### How the design meets the forces

F1: the posture table plus the registry extraction make the boundary a recorded, re-derivable fact. F2: seed-by-default leaves the GUI a first-class tuning surface; the reconcile touches two key families only. F3: the template whitelist is held by mechanism (reconcile) with the audit as backstop. F4: authoritative divergence is bounded by shell-start; seed divergence is visible in one script run. F5: convention was kept where it holds (#877), mechanism added only where a trust surface demanded it, nothing runs unbidden. F6: the authoritative list is an attrset in `home/nixos/noctalia.nix`, from which the reconcile script is generated and which the audit reads. F7: nothing here waits on upstream. F8: the per-bump audit mode diffs the registry against the recorded baseline.

## Premises

- **`deepMerge` replaces arrays and non-tables wholesale, recursing only into tables.** Verified at the pinned source (`src/config/config_service.cpp:1343-1355`, explicit upstream comment), 2026-08-17.
- **All four `[theme.templates]` keys are GUI-writable.** Verified: `settings_registry.cpp:812,831,845`; `settings_window_popups.cpp:2267` (`community_ids`), 2026-08-17.
- **Editing any idle row writes the entire behaviors collection, every leaf populated, serialised as a table of named rows.** Verified at source (`settings_window_popups.cpp:698-711`; `config_overrides.cpp:559-589`), 2026-08-17. **Not runtime-verified** — what a real UI edit lands in the sidecar (including whether upstream's dedup thins it) is de-risk item (iii).
- **The sidecar is hot-reloaded on external edit.** Runtime-verified on alcyone 2026-08-17 (reload within 1 ms of write, `colors_changed` re-fired).
- **`hooks.started` fires exactly once, after the sidecar is loaded and the watch is active, before the main loop polls; hooks exec via `/bin/sh -lc` with no env vars and stdio redirected to `/dev/null`.** Source-verified at beta.8 by the stage-4 sweep (`application.cpp:237-240`, hook executor via `runShellCommand` → double-fork `execvp`), adversarially confirmed, 2026-08-17.
- **Settings dedup is real, per-write-batch:** `overridePathEffectiveInTable` (`config_overrides.cpp:1525-1557`) erases a written path whose removal leaves the merged config structurally equal — covering scalars, tables and arrays, but only for paths in the current write call, never pre-existing keys elsewhere. Source-verified 2026-08-17; on-metal behaviour for the idle table is gate (iii).
- **No general IPC settings-write/override-clear verb at the pin.** Verified by full dispatch-table enumeration (~105 registered verbs across 24 files, every one a scoped single-purpose setter), adversarially confirmed, 2026-08-17. Ladder rung (a) is eliminated on this claim.
- The claim that *eliminated* an option: **continuous reconcile races the GUI** rests on the GUI rewriting the whole sidecar from memory on any settings change — now source-verified (`setOverrides` copies the full table, `commitOverrideTable` → `writeOverridesToFile` serialises it entire, `config_overrides.cpp:1868-1937,2678-2699`), 2026-08-17.
- **Upstream intent matches the seam this design builds on.** Noctalia maintainer, upstream issue #2858: declaratively-managed users are expected to hand-write `~/.config/noctalia/*.toml` rather than version the GUI overrides file — direct, maintainer-sourced confirmation of the config/state split's design intent (found by the stage-4 prior-art verifier, 2026-08-17).

## De-risk evidence

Stage 4 ran 2026-08-17 as a workflow of five Sonnet finder agents, each finding independently adversarially verified by a second agent prompted to refute it; the main session adjudicated disagreements (one finder returned stub data and was re-run; two finder verdicts were overturned by verifier counterexamples and the verifier's position adopted). Results per gate:

- **(i) GUI re-write-from-memory — resolved, with a twist.** Core mechanism source-verified and confirmed: every GUI write serialises the whole in-memory overrides table, but that table is fully re-populated *from the file* on external-edit reload, so a deletion survives later GUI activity under human-paced timing. The verifier then found the sharper hazard the finder missed: the own-write echo filter discards an *entire* inotify drain when the own-write flag is pending (`config_service.cpp:915-918`, aggregate-per-drain, not per-event) — an external edit coalesced into the same drain as an own-write echo is silently dropped and the reload never runs. The follow-up sweep confirmed this is structural *at startup specifically* (no `checkReload()` until the main loop polls, after `hooks.started` has fired). Also established: a sidecar parse failure wipes all overrides to empty, and one opt-in timer-driven write path exists (wallpaper automation, default off). **Consequence: ruling 2-bis — the reconcile moved pre-spawn**, where the whole hazard class is out of the path by construction. Residual on-metal confirmation of deletion-survival is now low-value and dropped.
- **(ii) TOML surgery — viable only with a structural post-check.** The finder's gawk prototype passed the real sidecar plus five prescribed adversarial shapes byte-exact and parse-clean; the verifier broke it with a sixth: a legal trailing comment on a table-header line defeats header detection and silently deletes an unrelated table — *while still passing a TOML parse check* (missing keys are valid TOML; parse validity cannot catch under-deletion). CRLF line endings cause silent no-op. Adopted verdict: surgery is safe against the writer's canonical output only; the mandatory gate is a structural post-check (exactly the target regions differ, else restore and flag), not a parser.
- **(iii) Idle write shape on metal — RESOLVED (alnair, 2026-08-19): whole-collection freeze confirmed exactly as the source-read predicted.** One GUI edit (lock timeout 600→660) wrote the entire `[idle.behavior]` collection — every row, every leaf, `behavior_order`, and the suspend guard's store path frozen verbatim. The dedup did *not* thin per-leaf: screen-off's values matched declared and persisted anyway, confirming dedup operates at the written path's granularity (the whole table). The audit classified the result correctly on its first real divergence report — FORBIDDEN on the frozen store path (exit 2), REDUNDANT on the six dragged leaves, DIVERGED on the genuine tune — with one wart it also surfaced: the GUI serialises numbers as floats (`660.0`) where Nix declares ints, and the string-level compare mislabelled numerically-equal timeouts DIVERGED; fixed with a numeric-equality branch in this change. Side-finding: Noctalia's own rewrite reproduced the no-EOF-newline shape, independently corroborating the post-check fix's premise.
- **(iv) `hooks.started` + IPC sweep — done** (first run returned stub data, caught by its verifier and re-run). All findings in Premises above: hook fires once post-load pre-poll, stdio to `/dev/null`, no env; no general settings IPC verb among ~105 — rung (a) eliminated on evidence, not estimate.
- **(v) Extraction — deterministic and bump-diff clean, but the "one honest gap" claim did not survive stage-6 review.** Byte-identical across runs; against beta.7 a clean +5/−0 path diff. Gate v's verifier found the helper-lambda idiom (~86 per-instance `bar.*`/`wallpaper.monitor.*` paths, none declared here); the **stage-6 reviewer then found a third idiom that broke the "none declared" claim outright**: the hooks family is registered in a runtime loop over `kHookKinds` (`settings_registry.cpp` ~2833) — so `hooks.colors_changed`, a declared store-path leaf, was GUI-writable while the manifest omitted it against its own admission predicate and the shipped audit certified it bucket-3. Fixed at review: the manifest gained `leaf hooks colors_changed`, the audit appends known dynamic families to the registry explicitly, and the extraction's segment class dropped `.` (eliminating ~38 value/i18n false-positive pairs). **The intersection, as the shipped audit now computes it: of the 16 leaf keys this repo declares, 15 are GUI-writable (idle leaves via the `idle.behavior` collection control, the hook via the dynamic `hooks` family); bucket 3 is exactly one key, `shell.setup_wizard_enabled`.** The posture model is load-bearing for the entire declared surface bar one key — and the episode is the strongest evidence yet for F8: the boundary was mis-certified twice by hand and once by tooling before converging, each time caught only by adversarial re-derivation.

**Stage-6 adversarial review (2026-08-17, independent subagent, verdict land-with-fixes)** — all three blockers fixed and re-verified before landing: (1) the `hooks.colors_changed` manifest omission above; (2) the note's drifting numbers, restated once from the shipped extractor's measured output; (3) the sidecar swap made an atomic same-filesystem rename — the original cross-device `mv` was copy-then-unlink, and a power cut mid-copy would have produced exactly the parse-error-wipes-all-overrides loss this design exists to avoid. Also fixed from the review: temp-dir leak at every start (EXIT traps do not survive a successful `exec` — verified), silent-death extraction on upstream refactor, silently-ignored unknown audit arguments, and the manifest parser asymmetry (Nix now fails eval on a malformed entry, matching the audit's loud reject). **Accepted as known limits of the awk tier, recorded not hidden:** a target header hand-edited to carry a trailing comment evades the strip — mitigated flag-only (the wrapper greps the final sidecar for residual target mentions and FLAG-logs, never removes; sandbox-verified); a multi-line string whose *content* contains a target-header line can have those content lines removed while all post-checks pass (requires operator collusion; the writer's canonical output cannot produce it); a hand-edited multiline array inside a target table produces a permanent fail-safe refusal loop visible only in `reconcile.log`, with the audit as backstop. The reviewer could not construct any input defeating the always-exec guarantee (empty/directory/FIFO/symlink/huge/CRLF sidecars all reach exec).

**First on-metal run (alnair, 2026-08-18)** — the guard's deployment found both a real shadow and a real bug. The pre-switch audit found alnair's sidecar carrying the worst shadow yet observed: `enable_community_templates = true` plus six unreviewed community ids (`antigravity`, `libreoffice`, `obsidian`, `zellij`, `lazygit`, `yazi`) and `helix`/`qt` added to `builtin_ids` — live since 2026-08-15, hours after #866 recorded that host as clean. Impact sweep (read-only): every HM-owned symlink intact (zellij `config.kdl`, yazi `keymap.toml`); the community templates wrote only their own files (`lazygit/config.yml` fresh-unmanaged, `yazi/flavors/`, `zellij/themes/`); obsidian's `$HOME` walk found no vault to edit on that host. Real exposure, no damage — and the strongest field validation of F3 to date. On first login through the wrapper, the fail-safe guarantees held exactly as designed (shell started through the wrapper's scope, sidecar untouched on refusal, FLAG + residual-FLAG logged) — but the refusal itself was a **false positive**: upstream's serializer ends the sidecar without a trailing newline, the rewrite's final kept line gains one, and post-check 2 counted the resulting diff artifact as an addition. The sandbox suite had missed it because its shadowed shapes ended at EOF, putting the no-newline line inside the removed set. Fixed by EOF-newline-normalising both diff inputs (`awk 1`), regression-tested against the captured alnair sidecar itself (5 lines removed, parse-clean), and re-reviewed before landing. Until the fix deploys, the guard on alnair is fail-safe-inert: refusing, flagging, not enforcing.

**The witnessed enforcement pass (alnair, 2026-08-18 18:00, post-#879):** first login through the fixed wrapper logged `reconciled: removed 5 line(s)` against the real accumulated shadow — `enable_community_templates = true`, six unreviewed community ids, `helix`/`qt` — with the timestamped backup created, the sidecar clean of every authoritative key, the shell running inside the wrapper's scope, and the audit then reporting 0/0/0. **The clean pass (alcyone, 2026-08-20, first boot after switch):** `clean: no authoritative keys in sidecar`, audit exit 0. Both halves of the design — never break the session, never silently enforce — carry on-metal witnesses on both desktop hosts; the fail-safe path was additionally exercised in production by the pre-fix false positive.

Still unverified, stated plainly: the echo-drain collision has been shown structurally possible but never observed live — and pre-spawn makes observing it unnecessary for this design.

## Drawbacks

- **Three postures is more model than two.** The seed class re-admits, deliberately and per the operator's ruling, the declared-inert-on-this-host state that ADR-048 eliminated for theme selection — a future flake edit to a tuned key silently does nothing. The audit makes this *discoverable*, not *impossible*; the operator has accepted tracking it. This is the note's largest honest cost.
- **The reconcile reverts operator action.** If the exception list ever drifts from the operator's actual intent, the machine "undoes what I did" — the worst desktop experience in this problem space. Mitigated by the list being two entries, whitelist-form, in the file the operator already reviews.
- **The registry extraction is a parser against upstream source layout** — grep-tier, and upstream refactors will break it. Accepted per ADR-032 (breakage is loud, the fix is cheap, the alternative — a real parser — is disproportionate).
- **The audit's honest scope is narrow.** It cannot say *why* a value diverged; an operator who does not run it gets no protection on seed keys. That is the ruling's shape, stated plainly.

## Rationale & alternatives

- **Two postures, declared = authoritative (lock everything declared).** The initial lean. Rejected by operator ruling against F2: it makes the GUI a read-only surface for every declared baseline and forces a flake edit for every tuning experiment. The felt difference was decisive — "click it or git it" is clean but wrong for a single-operator machine whose operator wants live tuning with periodic agent review.
- **Convention + audit only, no reconcile (fork 2 option A).** Insufficient against F3: a re-enabled template does not wait for an audit — it runs on the next theme change. The window must be bounded by mechanism, not diligence. Kept as the fallback if de-risk kills the reconcile.
- **Continuous reconcile (fork 2 option C).** Races the GUI's whole-file rewrites, produces the machine-fights-me experience, disproportionate for a two-entry list (F5). The whole-file-rewrite premise is now source-verified (Premises); stage 4 added a second strike — the aggregate-per-drain echo filter makes any in-session external write inherently swallowable, continuous or not.
- **Upstream fix (authoritative-key marking / override visibility).** Parked by operator ruling (F7): the loop designs against upstream as-is; the upstream ask (Draft B) is rethought after this note, informed by it. An upstream authoritative-key mechanism would retire the reconcile — recorded under Future possibilities, not depended on.
- **Do nothing.** The status quo is #877's convention for one table: the idle store-path freeze remains live, bucket 3 stays folklore, and every future bump silently reshapes the boundary.

## Prior art

- **The retired `hooks.started` polarity reconcile** (deleted at the G5 cutover, `git show b98329b~1:home/nixos/noctalia.nix`) — the proven slot and shape for a start-time re-convergence, IPC-based, compare-first. This note's reconcile is its successor with a file-surgery twist the polarity version never needed.
- **#877** — the template convention, audit grep, and recovery procedure this note generalises; its §Theming text becomes the per-key instance of the posture model.
- **[docs/research/noctalia-v5-native-theming.md](../research/noctalia-v5-native-theming.md)** — recorded the template-toggle shadowing exposure pre-cutover ("pinnable, but only until shadowed").
- **#770's "must-not-touch" seam and the #644 v5 migration** — the previous iterations of the same two-writer boundary, each solved for one key family; this note is the class-level pass.
- **Upstream's own model** — the include-merge ("the including file wins") and the read-only-config NixOS accommodation show upstream thinks about layering deliberately; the overlay-replaces comment in `deepMerge` is a decision, not an accident, which is why the local guard does not fight it (F7). Sharpened by the stage-4 sweep: the maintainer states the intent outright in upstream #2858 — declarative users are expected to hand-write `~/.config/noctalia/*.toml`, not version the GUI overrides — so this design builds on the seam upstream intends, not against it.
- **dconf/GSettings locks** (surveyed stage 4) — the closest existing authoritative-key mechanism, and an independent instance of this note's exact shape: layered databases where the user db (last writer) wins by default — seed semantics — with opt-in per-key locks as the authoritative exception, declared in NixOS via `programs.dconf.profiles`. Adopt the shape; the mechanism itself doesn't transfer (Noctalia has no lock concept — that gap is what the parked upstream ask would name).
- **plasma-manager** (surveyed stage 4, verifier-corrected) — ships all three postures under other names: `immutable` writes KConfig's native `[$i]` marker (true prevention, the dconf-lock analogue), `persistent` excludes a key from reset (seed), `overrideConfig` regenerates wholesale (the lock-everything this note rejected). Validates the posture vocabulary as convergent, not invented.
- **nix-darwin `system.defaults`** (surveyed stage 4) — unconditional `defaults write` on every activation: a reconcile whose cadence is the rebuild itself, and a real-world instance of universal-authoritative posture. Rejected here for the same reason lock-everything was, but it legitimises reconcile-at-a-natural-boundary over continuous enforcement.

## Unresolved questions
