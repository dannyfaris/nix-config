# Ephemeral root — enforcing reprovision-from-source with btrfs archive-rollback and a declared persist whitelist

**Status:** Proposed — design note (`docs/design/`). Not built. [#553](https://github.com/dannyfaris/nix-config/issues/553) (owner) · [#633](https://github.com/dannyfaris/nix-config/issues/633) (audit probe, re-scoped by this note) · [#631](https://github.com/dannyfaris/nix-config/issues/631) (Alcyone, inherits the proven result at bootstrap) · extends [ADR-034](../decisions/ADR-034-no-host-data-backup.md); expect an ADR on acceptance. Mechanism selection ran the selecting-tooling process (2026-07-25); the evidence base is [`../research/ephemeral-root-prior-art.md`](../research/ephemeral-root-prior-art.md).

## Summary

ADR-034 stakes disaster recovery on two claims and adopts no backup tooling on their strength: **every host is reproducible from the flake**, and **durable data already has homes off the host**. Nothing enforces the first claim — today it is tested only by an actual disaster. This design makes it machine-enforced at every reboot: a systemd stage-1 initrd service renames the previous `@root` into a timestamped `roots-archive/` entry (retained N days, then purged — never hard-deleted at boot) and creates a fresh empty `@root`, so nothing on `/` survives a reboot except paths declared on an explicit persist whitelist — the nix-community impermanence module, backed by a `@persist` subvolume, with each declaration living in the module that owns the state. `/home` and `/nix` stay persistent and untouched: the second claim's territory, deliberately out of this design's reach. Adoption: metis first — a short report-only probe inventory of its live root seeds the whitelist, then enforcement flips with the archive as the safety net — and Alcyone inherits the proven mechanism and whitelist at bootstrap (#631).

## Motivation

State is the one domain this config does not govern. Users, packages, SSH access, and the stances themselves are all declared whitelists with mechanical enforcement (ADR-033); the root filesystem is the inversion — blanket-allow, implicit, mutable, unenforced. Any process can write anywhere on `/`, the write survives forever, and nothing declares or notices it. ADR-034 stakes disaster recovery on reprovision-from-source and deliberately adopts no backup tooling — a bet that is only sound if the flake really captures everything a host needs, which today is checked exactly once: during an actual disaster. #553 frames the fix; the 2026-07-25 operator discussion (recorded on #553) set the direction this note designs.

**Forces — what any design here must satisfy:**

- **Whitelist > blanket, enforced not asserted.** Undeclared state must not survive a reboot; the whitelist must be a declared, reviewable artifact, and the enforcement mechanical — the same grammar as every existing stance.
- **metis proves; new hosts adopt at bootstrap.** A fresh host must never boot mutable — bootstrap is the cheapest adoption moment it will ever have. But the mechanism and the whitelist are proven on metis first — the attended, console-break-glass host, per the fleet's established validate-before-inherit discipline: a short report-only inventory seeds the whitelist, retention bounds the retrofit risk, and Alcyone inherits a hardware-proven result instead of debugging an initrd service mid-bring-up.
- **Retention, not destruction** (operator constraint, first-class). The previous root is archived for N days, never hard-deleted at boot: the archive is simultaneously the audit trail (the exact delta of what the whitelist missed) and the recovery escape hatch. A recovery runbook must exist — the prior-art sweep found retention attested but **no documented recovery workflow anywhere in the fetched set**, so this is designed here, not copied.
- **`/home` stays persistent.** The originating erase-your-darlings baseline (research §5, the run's strongest vote); ephemeral `/home` is explicitly deferred — its worst losses are auth cliffs the field has no documented experience with.
- **Fleet reality as verified, not as remembered.** The pin's initrd is systemd stage-1 by default; roots are flat `@`-prefixed btrfs subvolumes via disko; nested subvolumes already exist under `@root` on the live host; no fleet host has a hibernation path. The mechanism must fit these facts (§De-risk evidence).
- **Module-owns-its-state.** A module that creates state declares its persist paths alongside its other config — no central list. The whitelist mechanism must therefore expose a *mergeable* option surface that modules contribute to independently. No prior art exists for this convention (research §6); it is ours to design.
- **Boot-critical fail-safe.** The wipe runs in the initrd, on the path to an unbootable host. Any error in the rollback must fail toward "boot the old root" — never toward blocking `sysroot.mount` — and a one-boot kill-switch must exist for recovery and debugging.
- **Proportionate scope.** Darwin is mechanically out (no btrfs, different boot stack — ADR-034 already notes this); nixos-vm and mercury are retiring (#634) and never adopt.

## Design

**Layout.** One new subvolume per adopting host: `@persist`, mounted at `/persist` with `neededForBoot = true` (an impermanence hard requirement, upstream-asserted since 2026-01). Archived roots live in `roots-archive/` at the btrfs top level (subvolid 5), which is not mounted in the running system — the purge timer and the recovery runbook mount it transiently. Alcyone's disko layout ships `@persist` from bootstrap; metis's retrofit creates it online (`btrfs subvolume create`, no repartition — verified possible against the existing flat layout).

**The fresh root.** Created empty at each boot with `btrfs subvolume create` — the canonical archive-and-recreate idiom ([recovery-workflows research](../research/ephemeral-root-recovery-workflows.md) §3). No blank snapshot exists: that idiom belongs to the rollback (no-archive) scheme family, and an empty subvolume is exactly what a blank snapshot would contain. NixOS activation plus the impermanence bind mounts repopulate the root from the closure and `/persist`.

**The rollback service** (systemd stage-1 initrd): ordered after the backing device unit and `Before=sysroot.mount`, it mounts the top level, renames `@root` → `roots-archive/<ISO-timestamp>`, creates a fresh empty `@root`, unmounts, and exits. Rename is atomic and O(1) — no data copy, negligible boot cost — and carries nested subvolumes (`/var/lib/machines`, `/var/lib/portables` exist today) along with the archived root intact. Two safety properties are non-negotiable: any failure leaves the existing `@root` in place and lets boot proceed (log + a degraded-marker file the probe reports), and a kernel-cmdline kill-switch (`ephemeral.skip-rollback`, checked first) skips the rollback for one boot — editable at the systemd-boot menu with no rebuild. The kill-switch is recovery infrastructure, not merely a debug lever: a promoted root is consumed through exactly one kill-switch boot (§Rollout), since the service would otherwise archive it again immediately.

**The purge** runs in normal boot, not the initrd: a timer transiently mounts the top level and deletes archives older than N days, recursively (nested subvolumes require recursive delete — verified needed on the live host). The purge never touches the active root. Initial N = 30 days: the only figure attested in prior art (tsawyer87), and wide enough to cover monthly-cadence losses; revisited against probe evidence, not defended as more than a starting point. The retention window is sized together with `nix.gc`'s `--delete-older-than`: an archived root references store paths that garbage collection may strip, so a promotable archive needs its generation's closure alive ([recovery-workflows research](../research/ephemeral-root-recovery-workflows.md) §3 — a NixOS-specific coupling no surveyed ecosystem documents).

**The whitelist.** The impermanence module becomes a flake input; `environment.persistence."/persist"` holds the declarations. Module-owns-its-state is implemented by the NixOS module system itself: each repo module that creates state contributes its own `environment.persistence` fragment, and the options merge — no central list, and a module's state contract is readable next to the module. The seed baseline maps research §4 onto this fleet: `/etc/machine-id`, `/etc/ssh` host keys, NetworkManager (`system-connections` + `/var/lib/NetworkManager`), `/var/lib/bluetooth`, `/var/lib/nixos`, `/var/lib/systemd/{coredump,timers}`, `/var/log`, `/var/db/sudo`, `/var/lib/tailscale` — each landing in its owning module with its why-comment. `/var/lib/docker` is deliberately **not** an impermanence bind mount: it becomes a real `@docker` subvolume mounted at `/var/lib/docker` (bind-mount I/O overhead and snapshot-bloat are both attested; a large mutable tree wants a first-class mount).

**The probe** (#633, re-cut by this note): a normal-boot service diffs the just-archived root against the whitelist + closure and reports novel paths over the existing ntfy channel — drift detection from day one and the discovery mechanism for the desktop-state tail, which no prior art enumerates (research §4). The probe is permanent (a #551 rung-3 candidate), not pre-enablement scaffolding — #633's original one-shot pre-enablement audit gate died with the enforce-from-adoption direction.

**Rollout.** The VM test proves the mechanism first (§De-risk). metis then adopts: the probe runs report-only against its live root to inventory undeclared state and seed the whitelist; `@persist` is created online (no repartition); then enforcement flips, with the archive as the retrofit safety net. The flip and its first reboot happen with the operator physically at metis — that boot is the moment the unbootability class is live, and metis's break-glass is the physical console; enabling over SSH would volunteer for the worst version of the failure. Alcyone bootstraps last, inheriting the hardware-proven mechanism and whitelist in its disko layout from first boot (#631). The recovery runbook lands in the same change as the mechanism (the reconcile rule), translated from adjacent ecosystems' mature workflows ([recovery-workflows research](../research/ephemeral-root-recovery-workflows.md)) rather than invented. Its frame: OS regressions roll back via NixOS generations (untouched by this design); state recovery is normally file-level reflink extraction from an archive under a single top-level mount (`cp --reflink=always` — zero-cost, CoW-shared); full promotion is the last resort — rename the current root aside, snapshot the archive into place (never a raw `mv`: the copy boots, the archive survives re-promotable), and consume it through one kill-switch boot. `btrfs subvolume set-default` is banned as a promotion mechanism — inert under the fleet's explicit `subvol=@root` mounts, with independent persistence and deletion traps (verified, recovery-workflows §2). Before promoting, `btrfs subvolume list -o` shows what flattens: snapshotting is non-recursive, so nested subvolumes in the archive return as empty directories (acceptable for `machines`/`portables` — systemd recreates them).

**How the forces are met.** Whitelist enforced mechanically at every boot; metis-proves-then-inherit sequencing with the retrofit bounded by retention; retention with a designed recovery path; `/home`/`/nix` never touched by the rollback; the mechanism is built for the verified fleet (systemd stage-1 service, rename-archival carrying nested subvolumes, no hibernation interaction to guard); module-owns-its-state rides the module system's option merging; fail-safe direction plus kill-switch guard the boot path; Darwin and retiring hosts are named out.

## De-risk evidence

Verified 2026-07-25 against the pinned inputs, the live host (metis), and source:

- **The pin's initrd is systemd stage-1 by default**: `boot.initrd.systemd.enable` evaluates `true` for metis with its only definition in the nixpkgs module itself (pin `e2587caef70c`) — nothing in-repo sets it. Consequence, load-bearing for the selection: the scripted-initrd hooks (`boot.initrd.postDeviceCommands` / `postResumeCommands`) that most published rollback implementations use still *exist* as options but are **inert** under systemd stage-1 — that entire prior-art family cannot be copied here.
- **Nested subvolumes exist under `@root` today**: `/var/lib/machines` and `/var/lib/portables` are subvolume roots (inode 256) on live metis — systemd creates them. Rename-archival carries them; the purge must delete recursively.
- **metis disko layout** (`hosts/metis/disko.nix`): flat `@root`/`@home`/`@nix`, no LUKS, no disk swap — zram only, "no hibernate" is a recorded decision. The hibernation-race corruption class from prior art (initrd touches the subvolume before the kernel checks the resume image) is structurally absent fleet-wide as provisioned; systemd stage-1 ordering additionally sequences resume correctly if that ever changes.
- **impermanence is not currently an input**; adopting it is a new single-maintainer flake dependency on the boot path (`neededForBoot`). Its whitelist mechanics, `neededForBoot` assertion (upstream, 2026-01), and maintenance state are in the research note §2.
- **31 GiB RAM on metis** — tmpfs-as-root would be feasible; it is rejected on the retention force, not on capacity.
- **The recovery-workflow translation pass ran** (2026-07-25, three targeted agents: snapper/openSUSE · ZFS boot environments · btrfs-native): [`../research/ephemeral-root-recovery-workflows.md`](../research/ephemeral-root-recovery-workflows.md). The runbook's three verbs translate cleanly; `set-default` and boot-menu `rootflags` editing are ruled out with mechanisms; the promotion×wipe interaction and the GC-window coupling surfaced there and are folded into §Design.
- **The one retention precedent, re-verified at source** (was UNVERIFIED in the research run's adjudication — research §3/§8): tsawyer87's guide confirms the mechanics verbatim — `mv` of the old root to a timestamped `old_roots/` entry, purge via `find -mtime +30` feeding a recursive subvolume-delete helper. Two findings carry forward: its rollback rides `boot.initrd.postResumeCommands` — the scripted-hook family that is inert on this fleet's systemd stage-1 — so even the single precedent cannot be copied, only re-idiomized; and it documents **no recovery workflow**, confirming the runbook has no precedent in the niche.

**The VM test — the de-risk gate before any host adopts.** A `nixosTest` flake check (`checks.x86_64-linux.ephemeral-root-vm`), built together with the rollback module as its first consumer:

- *The disk:* built from the same disko declaration the hosts use, via disko's image machinery (`system.build.diskoImages` — availability in the pinned disko revision is itself unverified; the fallback is the upstream nixpkgs pattern of formatting an attached empty disk in a setup phase). Either way the VM's layout is the fleet's layout, so test-vs-host drift is structurally impossible.
- *The definition:* the node imports exactly what a host would — the rollback module, impermanence, a fixture persist declaration. The test driver's direct kernel boot runs the full initrd, so the stage-1 rollback service executes on every VM boot with no bootloader emulation. Variant nodes carry the paths that cannot share a boot sequence — among them kill-switch (cmdline baked in), sabotage (a failure injected into the rollback service's archive or create step, e.g. a top-level mount forced to fail), retention-zero, and the promote-then-kill-switch sequence.
- *The assertions:* an undeclared file on `/` does not survive reboot; a persisted file does; the archive entry exists, timestamped, and **contains** the undeclared file (the safety net demonstrated, not assumed); a nested subvolume rides into the archive intact; the kill-switch node's file survives two boots; the sabotaged node still reaches `multi-user.target` on its old root with the degraded marker set — the fail-safe direction proven somewhere a failure costs nothing; a retention-zero node's aged archive is purged recursively; the promote-then-kill-switch sequence boots the promoted state and resumes wiping on the following boot; and a nested subvolume rides a rename intact but flattens to an empty directory under promotion-by-snapshot (both halves of the adjudicated contradiction — [recovery-workflows research](../research/ephemeral-root-recovery-workflows.md) §4).
- *CI posture:* a locally-run gate on metis for now (KVM native, minutes per run; the driver's interactive mode is where initrd iteration happens). It graduates into CI by construction when #546 self-hosts the x86_64-linux leg on metis — same machine, same KVM, warm store — rather than by solving hosted-runner virtualisation now. The test is x86_64-only as sketched; the mechanism is arch-independent, but the claim stays scoped if Taygeta (#547) later adopts.

Still unverified beyond the VM test's reach:

- **impermanence × systemd stage-1 interaction** — bind mounts are stage-2 and expected orthogonal; confirmed in the VM test, not assumed.
- **Purge behaviour under disk pressure** (archive growth vs churn — CoW makes the rename free, but N days of cache churn is real space; measured in the VM test and watched by the probe).
- **Boot-menu `rootflags` editing as an interactive boot-once-into-archive path** — ruled out as a documented mechanism (initrd-driven mounts; no verified NixOS case — recovery-workflows §2); if ever wanted, it is empirically tested per-host first, never documented on faith.

## Drawbacks

- **A bespoke service on the boot-critical path.** The worst failure class is an unbootable host — a class this repo has never shipped a mechanism into. Fail-safe direction, the kill-switch, and the VM test bound it; they do not eliminate it, and the service is ours to maintain against nixpkgs initrd evolution.
- **The failure-mode inversion stands.** Every other stance fails closed and loud; a missed persist entry fails destructive and silent. Retention converts destruction into a discovery deadline (N days), not into zero — a loss noticed on day N+1 is still a loss.
- **A new single-maintainer input on the boot path.** impermanence is active but one person deep with a large issue backlog; the used surface is small (bind-mount generation) and the fallback (hand-rolled bind mounts) is real but costs the mergeable declaration surface.
- **The whitelist will be wrong on day one for the desktop tail** — no prior art enumerates it (research §4). That is by design (the probe discovers it, retention makes discovery cheap), but the first losses are real UX events on the operator's daily driver — metis feels the discovery cost so Alcyone doesn't — and honesty requires saying so up front.
- **Two-regime fleet.** Darwin hosts stay mutable; the eventual ADR must scope its claim to NixOS hosts rather than promising "one state policy."

## Cost

- **Disk headroom for N days of archived roots.** Rename-archival is free at archive time; the standing cost is the churn delta (caches, logs) held for the window — the snapshot-bloat pattern from prior art. The probe watches it; the purge bounds it.
- **A standing re-verification when the pin moves** stage-1 or btrfs semantics — the same class of per-bump ritual the Noctalia migration accepted, smaller surface.
- **Every new stateful module owes a persist declaration.** The module-owns-its-state tax is recurring and deliberate — it is the mechanism by which the whitelist stays deliberate instead of accreted.
- **Three windows must stay mutually coherent** — archive retention, `nix.gc --delete-older-than`, and the probe's report cadence. Retention shorter than GC keeps promoted archives bootable; reports faster than retention keep discovery inside the recovery window. A small standing coordination burden that did not exist before.

## Rationale & alternatives

The mechanism selection (selecting-tooling, 2026-07-25) weighed five candidates against the forces:

- **tmpfs-as-root** — rejected on the retention force alone: RAM cannot archive; a power cut destroys even the current root's contents with no recovery tier. Also the largest behavioural distance from the existing disko layout.
- **Scripted-initrd btrfs rollback** (the mt-caret/Guekka/tbx.at family, and the bulk of published prior art) — **rejected on verification, not on merit**: its `postDeviceCommands`/`postResumeCommands` hooks are inert under the pin's systemd stage-1 default. Copying the most-published pattern would ship a no-op.
- **impermanence module alone** — not a candidate on inspection: it declares persistence but contains no wipe. Without a wipe the whitelist is aspirational — precisely #553's critique of the status quo.
- **Filesystem-native impermanence** (upstream #255's snapshot-reset + rsync-back prototype) — experimental, author-labelled rough, no maintainer commitment; watched, not adopted.
- **Fully hand-rolled** (own wipe *and* own bind-mount whitelist) — rejected: re-implements a maintained module and, decisively, loses the merged-`environment.persistence` option surface that module-owns-its-state rides on.

**Chosen: the split.** A small hand-rolled systemd stage-1 archive-rollback service — the one component nobody ships, and the one that carries the operator's retention constraint — plus the impermanence module for the declaration surface. This is the Guekka split from prior art, re-idiomized for systemd stage-1, with retention added. Each half does the one thing the other cannot.

**Impact of doing nothing:** ADR-034's premise stays aspirational, the set-≠-enforced gap (#303) persists in the largest remaining domain, and every future host accumulates undeclared state from day one — including Alcyone, whose bootstrap is the cheapest adoption moment the fleet will ever see.

The bet is composition-novelty, not mechanism-novelty. In-repo: ADR-033 (stances as mechanically-enforced whitelists — the grammar this design extends to state), ADR-034 (the premise being enforced), and the Noctalia migration's validate-before-inherit discipline, extended one rung earlier here: the VM test precedes even metis, because the failure class is unbootability, not a broken shell.
