# ADR implementation audit — does each ADR's body still describe the tree? (2026-08-15)

Status: **point-in-time review artifact, not a decision.** Captured 2026-08-15 by Claude (Opus 5), operator-requested. Method: 12 agents over the 48-ADR corpus — six read-only slices of eight ADRs each, every slice asked to quote verbatim any claim an ADR makes about the tree (a status field, an §Implementation assertion, a named artifact) that the tree no longer bears out, then hand each finding to a second, adversarial agent instructed to hunt for the discharge — a later superseding ADR, an in-document dated correction, a §History line, a live module comment — and to **default to REFUTED when uncertain**. Findings the refutation pass could not kill were adjudicated by the operator; this artifact records what landed, what did not, and what was thrown away. Companion to [record-coherence-sweep-2026-07-07.md](./record-coherence-sweep-2026-07-07.md), whose adjudication principles this audit inherits and, in one case, failed to apply.

The prompting instinct is the inverse of the July sweep's. That one asked whether the *living* docs had caught up with the fleet; this one asks whether the *frozen* records ever misdescribed the tree in a way a future session would act on. The distinction is the whole game: an ADR body describing an older tree is working as designed, and only a claim that would send an agent to build, restore, or trust the wrong thing is a defect.

## Adjudication principles (what was dropped, and why — so it is not re-litigated)

Seven findings were refuted. Five died on the same principle, restated here because it keeps being rediscovered:

1. **An implemented ADR body describing an older tree is frozen historical record working as designed, not drift.** `docs/decisions/README.md` §Conventions carries two of the three parts: status moves along the declared lifecycle, and once a decision lands in code the ADR is immutable historical record — change lands via a new Superseding or Amending ADR, never a body rewrite. The lighter pair this audit actually reached for — an index status note, or an appended §History line — is not README §Conventions' wording; it comes from [record-coherence-sweep-2026-07-07.md](./record-coherence-sweep-2026-07-07.md) principle 1, which names both as the legitimate mechanisms for a superseded ADR ("as ADR-010 already received for ADR-042"). ADR-037 §Decision item 1, "**Frozen — the why.**", puts it harder still: "A dated, implemented decision can't go stale." Casualties of this principle: **ADR-007** (`NH_FLAKE` via `home.sessionVariables`, since parametrised — recorded by ADR-019, which names `nix-tooling.nix` explicitly); **ADR-005** (see below); **ADR-006** (gh-dash hand-bridged theme colours, since converted to ANSI-16 by #411 — recorded in ADR-041 §Consequences, which names gh-dash); **ADR-009** (the post-ADR-020 git split naming `git-identity-work.nix`, deleted in b51c92d/#727 when mercury retired — a host decommission, not a doc drift); **ADR-022** (the `just bootstrap` recipe and the hardware-config banner, filed as "planned as follow-up" and since shipped — intent fulfilled does not falsify the intent).
2. **A menu of enforcement rungs is not a claim of implementation.** ADR-037 was filed as falsely claiming its doc lints exist. It does not — see §"The audit's own errors" below.
3. **An in-document dated as-built correction discharges the plan item above it.** ADR-036 was filed for planning to remove the Stylix desktop target-writers while `home/nixos/stylix-targets-desktop.nix` still carries a `gtk` target. ADR-036 line 14 already carries the descope block (2026-06-18, #385) naming that exact delta, and the file's own header documents which targets #385 did remove.

### The ADR-005 case — why this write-up exists

ADR-005 was flagged for its nixd `options.{nixos,home-manager}.expr` example naming `nixos-vm`. That finding had **already been raised, adjudicated and explicitly recorded as a false positive** by the 2026-07-07 sweep, under a section titled "Adjudication principles (what was dropped, and why — so it is not re-litigated)", whose principle 3 reads: "nixd is parametrised, not hardcoded … only the ADR *body* mentions nixos-vm, as history. No live-config staleness. Dropped." The audit re-flagged it anyway, with the same evidence, thirty-nine days later.

That is the strongest available argument for writing these artifacts down and for the refutation pass reading them: the July record is what killed the finding the second time, and this record is what should kill it the third. A sweep that does not read its predecessor pays the same adjudication cost every time it runs.

## Confirmed findings and disposition

1. **ADR-042 — status said pending; the implementation is complete.** (MEDIUM) Front matter read `Accepted, Implementation pending (#524 re-scoped)` while every artifact §Implementation scopes is live: the `sshEdges` map in `lib/operator.nix` (genuinely narrowed per host — electra is a pure sink with no outbound key), the `authorizedKeys` derivation in both `modules/nixos/users.nix` and `modules/darwin/users.nix`, and the stance in `lib/stances.nix` asserting the rendered set equals the edge-derived set, CI-wired for all four hosts through `parts/checks.nix`. **Fixed in this change**: status → `Accepted, Implemented (#575, #576)`, with a §History entry recording the pair that actually landed it — #575 the behaviour-preserving refactor ("step 1 of 2"), #576 the data-only narrowing that completed it ("step 2 of 2", carrying the per-host authorization delta) — recording that #631/#636/#637 are later host enrolments *under* the already-narrowed shape rather than part of the narrowing, and recording that #524 is not the landing reference (it closed `not_planned` 2026-08-03).
2. **ADR-046 — same shape.** (MEDIUM) Front matter read `Accepted, Implementation pending (wired in #435 PR B)` while `parts/formatter.nix` carries the dprint block field for field — markdown plugin, `textWrap = "never"`, `emphasisKind = "asterisks"`, `getPluginList` for the hermetic wasm. #435 closed completed by #738. **Fixed in this change**: status → `Accepted, Implemented (#435 PR B, #738)`. No §History added — the ADR has none, and the landing reference now sits in the status text.
3. **ADR-018 — an unrecorded reversal on the auth path.** (MEDIUM, filed HIGH) §Implementation states `age.sshKeyPaths = [ "/etc/ssh/ssh_host_ed25519_key" ]`. `modules/nixos/sops.nix` sets no `age.sshKeyPaths` at all: sops-nix's upstream default derives the age identity from `services.openssh.hostKeys`, so the decryption key follows sshd's key locations from one knob — because two knobs naming the path independently was the anatomy of the #553 auth-lockout. The rationale lived only in `docs/design/ephemeral-root.md`; no ADR recorded the reversal. This is the one finding with a real hazard: an agent "restoring" the ADR-described pin re-creates the incident's shape on a persist host. Severity was corrected down because the tree already defends itself — the module's own eval assertion requires every resolved key path to sit on a `neededForBoot` filesystem, and `tests/ephemeral-root.nix` models exactly that mutant. **Fixed in this change**: a new §History section on ADR-018 naming the reversal, its single-knob replacement, and `ephemeral-root.md` as the canonical rationale. §Implementation's prose is untouched — the body stays as history; the §History entry corrects the record.
4. **ADR-025 — a §History entry that promises more than the body delivers.** (LOW) Its §History says the copy-paste example in §Rationale "was repointed to a live host in this sweep (#736)". The example names `host-metis`, and metis was decommissioned by #799 on 2026-08-11 without this ADR being swept. Unlike the surrounding matrix prose, which the ADR marks as the record of its own date, this sentence makes a standing claim that the body is current — so the frozen-record defence does not reach it. Recommended remedy: one appended §History line noting the example now names a decommissioned host and pointing at the live checks (`parts/checks.nix` `host-alcyone` / `host-alnair` / `host-electra` / `host-celaeno`). **Left unfixed** — the operator authorised only items 1–3 and this artifact; recorded here so the next sweep finds it adjudicated rather than novel.

## The audit's own errors

**1. ADR-037 / #870 — a false positive, stated plainly as an error of the process that produced this audit.** The original #870 asserted ADR-037 falsely claims its grep-class doc lints are built. It does not. Its front matter says `Accepted, Implementation pending`; §Enforcement opens "A menu, adopted lightest-first per ADR-032 Rule 1" and sorts that menu under two bolded paragraph leads — "Committed now" and "Adopted on evidence" — not under headings; §Implementation opens "Decision-only landing" and lists the doc lints as a future rung. "Committed now" is ADR-037's own wording for the rung it commits *to*, not vocabulary inherited from ADR-032 — the phrase appears nowhere in ADR-032, which supplies only the lightest-first Rule 1 the menu is sorted by. It marks the one rung whose justifying evidence (#338) already exists, so unlike the "Adopted on evidence" rungs below it, it waits on nothing; committed-to is still not landed. `docs/ci.md`:50 reads the ADR the same way and says so unambiguously — "any doc lint added later (ADR-037 §2 contemplates cited-path and link checks)" —. `docs/decisions/README.md`'s ADR-037 row is the weaker corroborator: "Grep-lint rung committed" simply repeats the ambiguity that produced the misreading, so it confirms nothing on its own. The refutation pass killed the finding on those signals; the negative scan it inherited (no doc-link, cited-path or index lint anywhere in `parts/checks.nix`, `scripts/` or CI) held, so #870 has been rewritten to the real, narrower item: the lints are still unbuilt.

The failure mode is generic and worth naming: an auditor reading an ADR for present-tense assertions will read a *decision to adopt* as a *claim of adoption* unless it is told to check the front matter and the section's own framing first.

**2. ADR-042's §History entry, as first drafted — a fabricated claim about repo history.** The pass that applied this artifact's fixes wrote, in ADR-042's new §History entry and in confirmed finding 1 above, that step 2's per-host narrowing "never landed as the single data-only PR anticipated" and had instead "accreted through the host enrolments" (#631, #636, #637). That is false. #576, "narrow `sshEdges` to the interim edge map", merged twenty-three minutes after #575, carries the per-host authorization delta table, and states in its own body: "This completes ADR-042's PR pair." The three enrolments (#631, #636, #637 — issues, not PRs) are later work under the shape #576 established, for hosts that did not exist when it landed. The claim did not come from the tracker — it came from the orchestrating spec, which asserted repo history from inference rather than from the tracker, and the applying pass wrote it through unchecked. A verification pass caught it before the change landed; both sites were corrected against #575/#576.

Recording it here is the point of this section, not an incidental. This artifact exists so the next sweep inherits settled facts instead of re-adjudicating them — which is precisely why a fabricated fact in it is worse than one in a PR body: it would have hardened into the settled record the next sweep trusts. Its shape is the mirror of error 1. There, an auditor read a *decision to adopt* as a *claim of adoption*; here, a spec-writer read an *absence of remembered evidence* as *evidence of absence*. Both are cheap to prevent by the same discipline — check the primary source before asserting what it says.

## Considered and rejected

Recorded so future sweeps do not re-flag: rewriting ADR decision bodies (falsifies history — principle 1, inherited unchanged from the July sweep); "fixing" ADR-005's nixd example (twice-adjudicated false positive); treating a fulfilled statement of intent as a falsified claim (ADR-022); treating an enforcement menu's "Committed now" as an implementation status (ADR-037); bumping ADR-039's status flat to `Implemented` (two named items genuinely outstanding — it needs a qualified status, decided on its own evidence, not as a rider on this change).

## Closing

Two status fields were lying about work that had landed; one reversal on the auth path had been made deliberately and recorded nowhere in the decisions corpus. All three are fixed here — in four record corrections, since ADR-018 takes a second §History entry for a `defaultSopsFile` path-depth change that came with the ADR-026 `core/` flatten (#132, 2026-05-31) and that ADR-018's own 2026-06-05 path sweep missed — by two mechanisms: a status bump along the lifecycle `docs/decisions/README.md` §Conventions declares, and an appended §History entry — the lighter alternative to a superseding ADR that the July sweep's principle 1 named, and that this one inherits. Everything else the audit turned up was either frozen history behaving correctly, a narrower finding than filed, or the audit's own misreading. The residue is one LOW finding on ADR-025, adjudicated and deliberately unfixed, and one qualified status bump on ADR-039 waiting on its own decision.
