# Noctalia v5 migration — adversarial audit of the design note's De-risk section

Status: **research note, not a decision.** Captured 2026-07-25 from a third adversarial pass (AI subagent) during the #644 design loop: an audit of [`../design/noctalia-v5-migration.md`](../design/noctalia-v5-migration.md) §De-risk *itself* — re-verifying every "verified at source" claim against a fresh read of `noctalia-dev/noctalia` @ tag `v5.0.0-beta.4` (commit `4c2dcd0995f9c570c0ced95561bf5e4685e2ad1b`), hunting coverage gaps in the probe plan, and attacking probe observability. All corrections and gaps listed here were absorbed into the design note before its acceptance (2026-07-25); the addendum records the build-gate datum. This note freezes the audit's full text.

## 1. Claim audit

All five metis live claims reproduced (gnome-keyring owns `org.freedesktop.secrets`; pipewire+wireplumber active; GLAN enabled + eno1 wakeup enabled; `HandlePowerKey=poweroff`, `IdleAction=ignore`; v4 settings.json: six templates disabled, `useWallpaperColors` false, idle disabled). Caffeine session-scoping (S4's rider) is already provable at source: `m_enabled` is never persisted.

**STRETCHED / to correct:**

1. **`lock-and-suspend` "3 s fallback"** — the timer is armed only inside `handleLocked` (lock_screen.cpp 426). It covers slow *surface rendering after* `locked`; the normal path additionally waits for `allSurfacesReady()` (372–378) — stronger than the note claims. But **if the compositor never emits `locked`, there is no fallback**: the pending suspend sits forever and the box stays awake. That failure direction matches the guard's posture, but the note's characterisation is wrong about what the fallback covers and silent on the never-locked case. Amend.
2. **"hard runtime deps include a running PipeWire + WirePlumber"** — package.nix shows link-time buildInputs; "a *running*" daemon requirement is not established by source. Immaterial on metis (both active) but reword.
3. **"outputs blank before any client paints"** — a compositor obligation of the ext-session-lock-v1 protocol (niri's side), not verifiable in noctalia's tree. True, but misattributed as noctalia source verification.
4. Line drift: `forceReload` is at 875 (not ~615); the Wayland-inhibitor-destruction logic is `syncInhibitor` ~183–197 (not 66–80). Substance verified both times.
5. Parser claim incomplete: if `light` is present without `light.terminal`, the *whole* parse fails (183–189), not just missing-`dark` cases. Harmless (render helper emits both) but worth precision.

## 2. Coverage gaps (ranked)

**Schema keys — all verified, no CRITICAL mismatch.** Every key in §Design's TOML sketch exists with the exact name: `shell.setup_wizard_enabled` (config_schema.cpp 1453), `theme.source`/`custom_palette`/`mode` (1149–1154), both template toggles (1107–1109), `hooks.started` (string or array accepted), `idle.pre_action_fade_seconds` (870), and `[idle.behavior.<name>]` is a namedMap under key `"behavior"` with fields `enabled`/`timeout`/`action`/`command` (830 ff) — the sketch's table-per-name shape is right, names are free-form. `action = "command"` is the canonical custom value. **Caveat:** the schema does *not* validate the action string — any typo silently falls through to command mode, so `validateConfig` will not catch it. Note this.

**(a) HIGH — package build vs pinned nixpkgs: no probe existed; datum now in hand.** `nix eval` of the flake's `drvPath` with `nixpkgs` overridden to the metis pin **succeeds** (all attrs resolve; drv `/nix/store/xxk0x2izdbzcw30vnjdkyq6dchaabsk5-noctalia-5.0.0.drv`). The full compile was launched (result in the addendum). Add **C0: build the input's package against the repo pin** as a pre-implementation gate regardless.

**(b) HIGH — probe C2 contradicts the design's own started-hook.** The hook fires `theme-mode-set` on every start, which persists `theme.mode` into `settings.toml` immediately — so "first start writes no theme overrides on day one" fails *by design*. Scope C2 to "no overrides other than the hook's `theme.mode`", or make the hook compare `theme-mode-get` first. Also: C2 is single-shot (only observable on the very first start; state dir wipe to repeat) — flag the ordering constraint.

**(c) MEDIUM — hook timing chicken-and-egg: resolved favourably at source, absent from the note.** `initIpc` phase precedes the "startup hooks" phase (application.cpp 229–234); hooks run via `/bin/sh -lc` on a detached thread (process.cpp 789–793); the client has 2 s timeouts and the main loop starts immediately after — the hook's `noctalia msg` lands in the socket backlog and is served. Add as a Verified-at-source bullet. Related, resolved: `theme-mode-set` on an unchanged mode persists idempotently and re-resolves, but `startTransition` short-circuits on an equal palette (566) — **no spurious animation**. One startup nuance to record: the shell first paints with the stale persisted mode, then converges — one visible flip when dconf and the echo disagree.

**(d) MEDIUM — V5's answer is already determined by source + live fact, and it reveals a design gap.** metis's session is `wayland-1` (verified); with `WAYLAND_DISPLAY` unset the client guesses `wayland-0` → any `theme` run over SSH into a live session *silently skips the Noctalia repaint* — a regression vs v4's copy+watch, which worked from anywhere. The CLI should discover the socket (glob `$XDG_RUNTIME_DIR/noctalia-*.sock` or export the display). Reframe V5 from "learn the socket name" to "validate the CLI's socket-discovery strategy".

**(e) LOW — no probe exercises the real idle fire path for `action = "command"`** (S3 dry-runs by hand, not from noctalia's `/bin/sh -lc` spawn env). The guard as `writeShellApplication` is PATH-self-contained, so risk is low; still, add a short-timeout probe with the guard in dry-run mode writing a marker file. **(f) systemd-lock-handler:** verified in the pin (`nixos/modules/services/system/systemd-lock-handler.nix`) — user-level `lock`/`unlock`/`sleep.target` bridging, matching §Design's mechanism; cite the module path.

## 3. Probe-plan fixes

- **V2:** "one ~400 ms transition" by eye is weak (`kTransitionDurationMs = 400` confirmed). Sharper: spawn with `NOCTALIA_PROFILE=1` (scoped_timer.h) — each resolve logs a `theme: resolveAndSet` timer line to stderr; assert exactly one line per switch, zero after a repoint without IPC, plus before/after screenshot pixel sampling. Prerequisite probe V0: identify where noctalia's stderr lands (greetd/niri journal) — V1/V6's "log warning" criteria depend on it.
- **V6 is impossible as phrased:** `color-scheme-set` *validates existence* and refuses missing palette names (config_overrides exists-check). Reformulate: temporarily break the symlink target (rename the state file), `config-reload` → fallback + warning; restore.
- **Destructive/order flags missing:** S2, S4, S5 all end locked or suspended — each needs a body at the keyboard, not just S5; run them last, S4 before S5. V3 kills the live shell mid-session; S4 needs a config edit (state-changing). C2 must be the first-ever v5 start.
- **S3** presumes a guard dry-run mode that §Design never specifies — add a `--dry-run` flag to the guard's spec.
- **S5** is observable as written (systemd "Finished <unit>" vs kernel `PM: suspend entry`, same journal clock); strengthen by also asserting the user `sleep.target` activated, proving the handler bridge rather than coincidence.
- **C6** names no instrument: define as font-switch → hint-path screenshot → shell restart → screenshot; identical renders = no cache.

## 4. Process gap — verdict: yes, fix it

"Session-recorded" points at an artefact that exists nowhere in git, contrary to the repo's own rules (CLAUDE.md: agent memory is per-host scratchpad; docs/design/README.md: "record what was verified and where"; precedent: `docs/research/omarchy-theme-switching-validation.md`). Mitigating: the reviews' substantive findings *are* absorbed into the section and all reproduce from source, so the note is self-sufficient. Minimal fix: drop the "session-recorded" pointer and state the findings are fully absorbed here (transcript not retained); optionally freeze the fuller reviews as `docs/research/noctalia-v5-*.md` if they contain evidence beyond the note.

## 5. Bottom line

**Sound after amendments — amend, don't restructure.** The source-verification layer is unusually accurate (every load-bearing claim reproduced). What needs fixing: two mischaracterisations (the 3 s fallback semantics + the never-`locked` residual; "running PipeWire"), one misattribution (protocol blanking), one internally inconsistent probe (C2 vs the started-hook), one impossible probe (V6 via IPC), one probe whose answer is already known and exposes a real CLI design gap (V5/SSH socket guess), a missing top-of-plan gate (C0 build-against-pin), and the process-gap wording. None undermines the chosen design; the constant-name palette seam and the guard's fail-awake direction both survive adversarial reading.
