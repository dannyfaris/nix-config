# ADR-049: Noctalia config postures — seed by default, authoritative by exception

> Every Noctalia key this repo declares carries a **decided posture** governing what a GUI override of it means. **Seed** (the default): Nix states the baseline, the operator tunes freely in Noctalia's settings UI, and the override legitimately wins — divergence is visible on demand, never fought. **Authoritative** (the exception, whitelisted once in `home/nixos/noctalia-authoritative-keys.conf`): a GUI override is a fault regardless of content, reverted at session start — the `[theme.templates]` table (trust surface: which scripts may run) plus every declared leaf whose value is a store path (today `idle.behavior.suspend.command` and `hooks.colors_changed` — nobody tunes a store path in a GUI; its presence in the sidecar is only ever rot). **Delegated** (unchanged from [ADR-048](./ADR-048-noctalia-theming-delegation.md)): nothing declared, the GUI owns the key family outright. Enforcement is a **pre-spawn reconcile** (niri launches the shell through `noctalia-guarded-launch`, which strips authoritative overrides before the process exists) paired with a **read-only audit** (`scripts/noctalia-config-audit.sh`) that classifies sidecar divergence and re-derives the GUI-writable registry from the pinned source per bump. **Amends ADR-048 §Decision item 1's scope**: "declared-vs-runtime disagreement is impossible by construction" is true of theme *selection* (where nothing is declared) and was never true of the declared surface — Noctalia's layering is per-setting last-writer-wins with the sidecar loading last, and at the pin 15 of this repo's 16 declared leaves are GUI-writable.

## Context

ADR-048 delegated theme selection to Noctalia by declaring no theme keys — one writer, structurally. That guarantee was read as extending to the whole declared surface; #866 showed it does not: a GUI tick wrote a complete `builtin_ids` array into the sidecar, wholesale-replacing the reviewed template whitelist and re-enabling the deliberately disqualified `starship` template, silently. Upstream's `deepMerge` replaces arrays and scalars wholesale by explicit design, and the settings registry at the pinned `v5.0.0-beta.8` makes essentially every declared key GUI-reachable — including via idioms invisible to literal source extraction (per-instance helper lambdas; a per-HookKind runtime loop that exposes the declared `hooks.colors_changed` store path). The operator's ruling set the central force: the GUI must remain a legitimate live-tuning surface for declared baselines ("I back myself to keep track… an agent should be able to periodically review active vs declared"); lock-everything was considered and rejected. Full forces, alternatives, and the two-stage adversarial de-risk record live in [`docs/design/noctalia-config-surface-overlap.md`](../design/noctalia-config-surface-overlap.md), the design note this ADR freezes — not restated here (ADR-032 single-sourcing).

## Decision

**1. Three postures, assigned by rule, not per-key deliberation.** Seed is the default for everything declared. Authoritative is a whitelist of exceptions admitted by predicate: template enablement (a trust surface — ticks change which scripts run on the host), and any declared leaf whose value is a store path (divergence is decay, never preference: the sidecar copy rots when a rebuild moves the path). Delegated remains ADR-048's posture for taste. A key the operator finds themselves tuning permanently is a candidate for *undeclaring*, not a new posture.

**2. One manifest, two consumers.** `home/nixos/noctalia-authoritative-keys.conf` is the single source: parsed at eval by `home/nixos/noctalia.nix` to generate the reconcile (a malformed entry fails eval), read verbatim by the audit (same reject, loud). The two guards cannot disagree about what is protected.

**3. The reconcile runs pre-spawn, and the session always starts.** niri's `spawn-at-startup` launches the shell through `noctalia-guarded-launch`: check the sidecar, strip authoritative keys if present (backup first, structural post-check before an atomic same-filesystem swap), then `exec` the shell — unconditionally, from every path, on every failure. Pre-spawn rather than the retired `hooks.started` slot because the in-session alternatives all fail structurally at startup (the aggregate-per-drain inotify echo filter can silently swallow an external edit; a sidecar parse failure wipes every override; the file is live under a watcher). The structural post-check — every removed line is a target header, key line, or blank; nothing added; no target survives — is the safety gate, because TOML parse validity is provably blind to under-deletion. Enforcement is flag-not-fix at the margins: shapes the awk tier cannot safely strip (hand-edited headers with trailing comments) are FLAG-logged, never guessed at.

**4. The audit reports mechanical facts; judgment stays with the operator.** `scripts/noctalia-config-audit.sh` (read-only, exit 2 on a forbidden hit) classifies sidecar leaves as FORBIDDEN / REDUNDANT (equal to declared — worth clearing, since it silently blocks future flake changes) / DIVERGED (a diff for the operator; tuned-vs-dragged is not machine-decidable and is not guessed). `--bump-check` re-derives the GUI-writable registry from the pinned source against the checked-in `scripts/noctalia-gui-registry.baseline` and re-classifies every declared key's reachability — the boundary is a re-derivable fact of each pin, not folklore, and a bump that makes a declared key newly GUI-writable surfaces as a diff. Run after any control-centre session touching declared keys and as a named step in the per-bump ritual (`docs/desktop/noctalia.md` §Sharp edges); never a timer.

**5. ADR-048 §Decision item 1 is amended in scope.** The one-writer-by-construction guarantee holds exactly where nothing is declared — theme selection. For declared keys the true model is per-setting last-writer-wins with the sidecar loading last (upstream-documented for scalars; source-explicit for arrays and tables via `deepMerge`'s "overlay replaces base wholesale"). ADR-048's structural guarantee is therefore the *delegated posture's* property, and this ADR supplies the machinery for the other two postures that item 1's wording elided. Recorded in ADR-048 §History; its body stands per the immutable-body convention.

## Rationale

**Seed-by-default over lock-everything (operator ruling, 2026-08-17).** Locking every declared key makes the GUI a read-only surface and forces a flake edit for every tuning experiment — "click it or git it" is clean but wrong for a single-operator machine whose operator wants live tuning with periodic agent review. The accepted cost, named plainly: a future flake change to a tuned key silently does not apply on that host until the override is cleared; the audit makes this discoverable, not impossible. Prior art independently converges on the same shape: dconf's layered model (user db wins, opt-in per-key locks) and plasma-manager's `persistent`/`immutable`/`overrideConfig` triple are this ADR's three postures under other names.

**Pre-spawn over in-session enforcement.** Chosen on stage-4 source evidence, not preference — every in-session slot inherits at least one of: the startup echo-drain swallow, the parse-failure total-wipe, or a live-watcher race. Editing the file before the process exists has none, by construction. Mid-session ticks persist until the next session start; the audit is the backstop, and severity does not warrant continuous enforcement (ADR-032; a continuous reconcile also races the GUI's whole-file rewrites — the machine-fights-me experience).

**Flag-not-fix at the enforcement margins.** The reconcile refuses and FLAGs rather than guessing when the sidecar's shape defeats safe surgery. Its production debut proved the direction right: the first on-metal run refused a *correct* rewrite (upstream serialises no EOF newline; the post-check counted the normalisation artifact as an addition) — the session started, nothing was corrupted, the log told the truth, and the fix (#879) shipped before any enforcement happened. Fail-safe-inert is a recoverable state; a wrong write to the file that holds every runtime preference is not.

## Consequences

- ✓ A stray tick can no longer durably change which template scripts run: authoritative overrides live at most until the next session start. Witnessed on alnair: a real accumulated shadow (`enable_community_templates = true` + six unreviewed community ids) reconciled on first login through the fixed wrapper.
- ✓ The declared-vs-GUI boundary is decided and re-derivable per pin — 15 of 16 declared leaves GUI-writable at beta.8, bucket 3 exactly `shell.setup_wizard_enabled` — instead of an accident nobody had mapped.
- ✓ Live tuning stays first-class; the GUI is never fought over seed keys, and the audit's divergence report is the operator's ledger.
- ✗ Seed keys reintroduce, deliberately, declared-value inertness: a tuned key's flake value is dead on that host until the override clears. Gate (iii) sharpened the cost: one GUI idle edit freezes the *entire* collection, every leaf, dragged values included.
- ✗ Two grep-tier parsers (the reconcile's awk surgery, the audit's registry extraction) ride upstream's source and serializer shapes; both fail loud rather than silent, and both are re-verified per bump — but they are maintenance surface a native upstream mechanism would retire.
- ⚠ Migration trigger: an upstream authoritative-key marking or override-visibility mechanism (the #866 upstream ask, reframed away from array-merge — which `deepMerge`'s comment shows is deliberate) would retire the reconcile and shrink the audit to seed-key reporting.
- ⚠ Migration trigger: if `enable_community_templates` is ever flipped per ADR-048's own per-id gate, the authoritative table's stakes rise from "unreviewed builtin" to "arbitrary fetched `apply.sh`" — the posture machinery is the precondition, not the gate itself (#867's acceptance gates are).
