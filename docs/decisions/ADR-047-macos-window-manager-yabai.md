# ADR-047: yabai + skhd as the macOS window manager

> Adopt **yabai + skhd** as celaeno's window manager, superseding [ADR-040](./ADR-040-macos-window-manager-aerospace.md)'s AeroSpace decision. SIP stays **enabled** throughout the trial and the adopted config — yabai's scripting addition is **not used** (`enableScriptingAddition = false`, stated explicitly rather than left to the upstream default). Native macOS Spaces return as the workspace layer — yabai's CLI/API term "Space" and Mission Control's UI term "Desktop" name the same object, used interchangeably below — reversing ADR-040's single-native-Space model: nine Mission Control Desktops, with `Hyper+1‑9` wired to macOS's own Switch-to-Desktop shortcuts to keep the native slide. Verdict **GO** after a two-day live daily-driver trial on celaeno, confirmed through two cold boots — the first exposing the borrowed-shortcut reset that is now declared away, the second clean end-to-end.

## Context

[ADR-039](./ADR-039-capability-registry.md) §7 and the design note [`macos-deterministic-tiling.md`](../design/macos-deterministic-tiling.md) both rejected yabai on the same ground, each stating it at a different remove: ADR-039 §7 compresses the rejection to "yabai (SIP)"; the design note's immovable force 2 states "No SIP. Accessibility-API only … (rules out yabai)"; the verbatim reasoning behind both — "its scripting addition requires partially disabling SIP" — is [`docs/desktop/macos-window-management.md`](../desktop/macos-window-management.md) §Rejected alternatives, the canonical selection record behind ADR-039 §7. That rejection was scoped to a component this config does not use. yabai's own [CHANGELOG](https://github.com/koekeishiya/yabai/blob/master/CHANGELOG.md) records 7.1.19 as "space --focus command now works with SIP enabled" and 7.1.25 as "Functionality for moving windows between spaces works with SIP enabled again" — SIP enabled meaning the non-scripting-addition path, since the scripting addition cannot load under SIP — the gesture and window-management paths the trial exercises. The 7.1.25 path was additionally confirmed live on-box during the trial (§History, 2026-08-11 activation entry). The disqualifying premise no longer holds for the feature set this config actually needs.

This is explicitly **not** one of ADR-040's own migration triggers. ADR-040 named two: AeroSpace proving unreliable or its upstream stalling, or a SIP-free scrollable-columns tiler maturing. Neither happened — AeroSpace neither destabilised nor stalled, and no scrollable-columns macOS tiler matured. The operator is exercising authority to reverse a frozen decision on the strength of a live trial, not responding to a named trigger firing. This ADR does not relitigate the original yabai-vs-AeroSpace selection or the "i3 tree, not scrollable" framing that decided it; it reopens one premise (the SIP clause) on new evidence and lets the rest of that reasoning stand as history.

The honest posture this reopens, stated in [`modules/darwin/yabai.nix`](../../modules/darwin/yabai.nix)'s header: force 2's first clause — SIP stays enabled — holds; `enableScriptingAddition = false` means no Dock injection and no SIP change. Its second clause, "Accessibility-API only," does not hold for yabai the way it held for AeroSpace. This config exercises private SkyLight throughout — for example `SLSMoveWindowsToManagedSpace` — plus a synthesized private gesture stream for space switching, where AeroSpace was public Accessibility API plus one private window-ID call; the per-call-site citations are in [`modules/darwin/yabai.nix`](../../modules/darwin/yabai.nix)'s header. The posture question this ADR actually answers is **"is SIP-enabled-but-private-API-heavy acceptable"**, not "is yabai Accessibility-only." It is not Accessibility-only, and that distinction is not softened here.

## Decision

Adopt **yabai** as a nix-darwin *system* service on celaeno (`services.yabai`), with `enableScriptingAddition = false` stated explicitly in the config rather than inherited from the upstream default — enabling it would write a passwordless-root sudoers rule for the whole admin group and require SIP off, a posture consequential enough to state rather than assume. Layout is **BSP with `auto_balance`**, the nearest analogue to AeroSpace's `tiles`: yabai has no i3-flat layout, so equal-area siblings via auto-balance stand in for it.

**skhd** becomes the hotkey daemon, replacing AeroSpace's built-in bindings entirely — yabai has no hotkey engine of its own. Chords are single-sourced from `lib/capabilities.nix` (ADR-039's registry), one per darwin-realized capability; command bodies are hand-authored in `home/darwin/skhd.nix`, keyed by capability id, with a both-directions completeness assert (a capability with no body, or a body with no capability, fails at host eval). The trade is stated honestly, as `skhd.nix`'s own header states it: **the registry owns the chords, not the actions** — weaker than the AeroSpace arrangement, where simple verbs (focus, move, workspace) lived in the registry itself via the `aerospace-action` emitter. Under skhd, every darwin realization is a hand-authored body, because skhd bodies resolve the yabai binary by package-derived absolute path, which the repo-decoupled registry (`{ lib }` only) cannot form.

**Native Mission Control Desktops (nine) are the workspace layer**, reversing ADR-040's single-native-Space model. `Hyper+1‑9` does not call `yabai -m space --focus` — it synthesizes macOS's own "Switch to Desktop N" shortcuts, declared in `home/darwin/symbolic-hotkeys.nix` (re-imported at every activation; they do not survive a reboot undeclared) — to keep the native slide. Only `Hyper+Tab` (`space --focus recent`) rides yabai's SIP-free gesture path — an instant cut with no dependency on declared shortcut state, kept because it has no numbered target to borrow. The `Hyper+←/→` edge-scroll's plain step and wrap are both synthesized macOS shortcuts instead: the step synthesizes Move-a-space (`Ctrl+←/→`, enabled by default), and the wrap synthesizes a numbered Switch-to-Desktop (`Ctrl+N`), because Move-a-space does not wrap and the wrap must therefore be a jump. This is a **deliberate inconsistency**, not an oversight: the gesture cut and the synthesized slide feel nothing alike, and the keypress-rejection trade attaches to each differently — `DISPLAY_IS_ANIMATING` is yabai's own rejection status on its space-focus commands, so it applies to the gesture path, which still serves `Hyper+Tab`; the synthesized-shortcut slide has no status channel at all, so a keystroke arriving mid-slide is silently dropped by macOS with nothing to observe. The accepted trade: the native slide is longer than yabai's cut, so rapid switching drops more keypresses than the gesture path did — dropped silently on the slide path, rejected with `DISPLAY_IS_ANIMATING` on the gesture path. The stakes of this split are concrete: the first cold boot's reverted Mission Control shortcut group killed `Hyper+1‑9` and the edge-scroll's chords together — 9 + 2 = 11 of 41 binds — because both depend on the same declared shortcut state the gesture path does not (§History, 2026-08-12).

A **SwiftBar menu-bar Desktop indicator** is pushed by a yabai `space_changed` signal (`modules/darwin/yabai.nix`), so it tracks a trackpad swipe or Mission Control just as well as a keybind. **The Karabiner Hyper substrate is unchanged** — the Caps→Hyper production stays exactly as ADR-040 left it. **JankyBorders continues under yabai** — it tracks the window server, not the window manager — but was re-tuned during the trial: the border thinned and the inactive colour faded to 50% alpha (`modules/darwin/jankyborders.nix`).

The darwin realization in the registry collapses from AeroSpace's two-type split (`aerospace-action` emitted, `aerospace-exec` hand-authored) to a single `skhd-exec` realization — chords in the registry, bodies hand-authored in `home/darwin/skhd.nix` — since skhd has no verb emitter to parallel `niri-action`; every darwin bind is now a body. This collapse, and the rest of the AeroSpace decommission, lands with this ADR (see §Implementation).

## Rationale

The operator's assessment after two days of daily-driver use: *"very happy … the native macOS spaces integration is working well and it generally feels less flakey than AeroSpace did."*

The measured case behind that: 18h+ continuous uptime at 0.0% CPU for yabai, skhd and SwiftBar alike, with zero bytes ever written to yabai's stderr during normal operation; two cold boots, with everything yabai owns surviving both and the daemons clean at the process level throughout — the first boot nonetheless silently reverted the borrowed Mission Control shortcuts, killing 11 of 41 binds and forcing them to be declared in `home/darwin/symbolic-hotkeys.nix`, so only the second boot was clean end-to-end; crash recovery verified for real, not assumed — both `SIGTERM` and `SIGKILL` respawn correctly, because launchd reports a signal death as non-zero exit and `KeepAlive.SuccessfulExit = false` only suppresses respawn on a *clean* exit (the precondition-failure case, where respawning would loop). The respawned daemon re-reads its config: rules, layout and the SwiftBar signal all return.

**What failed was never yabai.** Every defect found during the trial was in something bolted around it — the borrowed macOS shortcuts resetting on reboot, SwiftBar's Sparkle updater fighting a read-only store, a menu-bar plugin that is not nix-aware. Not one was in the tiler itself.

`window --toggle zoom-fullscreen` is a **stable, reversible maximise** — AeroSpace could not offer this at all; its only built-in maximize (`fullscreen`) silently drops on focus-change, forcing AeroSpace's one-way maximise-by-isolation workaround. This answers the standing need behind [#491](https://github.com/dannyfaris/nix-config/issues/491) and [#492](https://github.com/dannyfaris/nix-config/issues/492), left open under ADR-040.

**On how this was validated**, stated as sharply as the trial's own findings demand it: four diagnoses made during the trial were wrong — the `is-visible` filter, home-manager's symlink swap, a TCC posting permission, and "on by default" — and three of the four would have shipped as fixes if not caught. Every one was caught by running something on the box, never by reasoning or review; the two conclusions held most confidently from source-reading were among those falsified. The one deliberately written to *confirm* a fix instead disproved it and found the real cause. ADR-040 was itself reversed on the strength of a live trial; this trial says the same thing more sharply, and this is the repo's set-≠-enforced rule (CLAUDE.md §Conventions) with its sharpest evidence yet.

## Consequences

- ✓ **Native Spaces, Mission Control, and native fullscreen return** — reversing ADR-040's sharpest accepted divergence from stock macOS. The permanent relearning cost ADR-040 accepted is undone.
- ✓ **Stable reversible maximise** (`zoom-fullscreen`) where AeroSpace had none — answers #491/#492.
- ✓ **Trial-verified stability**: 18h+ at 0.0% CPU, zero stderr bytes, two cold boots with everything yabai owns surviving both (the first silently lost the borrowed-shortcut binds, now declared away; the second was clean end-to-end), verified crash-and-respawn behaviour.
- ✗ **Private-API exposure makes macOS point releases a live risk** in a way they were not for AeroSpace's public-API design — the SIP-free paths are private-SkyLight-heavy, not Accessibility-only (§Context).
- ✗ **The Keyboard Shortcuts panel is no longer authoritative on this host** — `Hyper+1‑9` and the edge-scroll wrap depend on `com.apple.symbolichotkeys` state that is now declared in `home/darwin/symbolic-hotkeys.nix` rather than left to System Settings.
- ✗ **Float rules are hand-maintained.** AeroSpace had its own window-detection heuristics; yabai has none, so `modules/darwin/yabai.nix`'s float rules are hand-listed and will need extending as new apps are added.
- ✗ **`Hyper+Tab` keeps an instant cut** — it has no native macOS equivalent to borrow the way `Hyper+1‑9` does, so it stays on yabai's gesture path alone; the edge-scroll's step and wrap ride the synthesized native slide instead (§Decision).
- ✗ **Multi-display is unexercised** — celaeno is single-display; the interaction between nine fixed Desktops and a display connect/disconnect is untested.
- ✗ **yabai cannot create Spaces itself** — `space --create` is scripting-addition-only, so the nine Desktops are a manual, non-declarable prerequisite rather than something the config can provision.
- ✗ **The Accessibility grant is keyed to the store path** (both binaries are ad-hoc signed, no Team Identifier) and is therefore lost on every version bump — re-granting is a manual step after every `nix flake update` that moves either package.
- ⚠ **Open, not decided here — pinning `pkgs.yabai`.** `lib/version-gate.nix` is the precedent for pinning a package against unstable's rolling churn; whether yabai warrants the same treatment, given the private-API exposure above, is flagged as a live question and deliberately left undecided by this ADR.
- ⚠ **Migration trigger — a macOS point release breaks the private SkyLight paths.** The risk: an OS update changes or removes the private symbols §Context lists, since yabai has no public API to fall back on the way AeroSpace does. Symptom space: space-switch/window-move binds (`space --focus`, `window --space`) going dead or erroring, surfacing — if at all — in `~/Library/Logs/yabai.err.log`; `launchctl list` is not the signal, since both daemons exit 0 on precondition failure (§Rationale). Levers, not decisions: pin or roll back `pkgs.yabai` (the `lib/version-gate.nix` precedent above — the pinning question stays deliberately open), or fall back to the AeroSpace configuration [ADR-040](./ADR-040-macos-window-manager-aerospace.md) records, preserved in git history.

## Implementation

The trial branch (`trial/yabai`) is the implementation. The AeroSpace decommission lands in the same PR that merges this ADR: deleting the AeroSpace module and its `aerospace-action`/`aerospace-exec` registry realizations (collapsing to a single `skhd-exec` realization — chords in the registry, bodies hand-authored in `home/darwin/skhd.nix`, per §Decision), re-pointing the lints and tests that reasoned over the AeroSpace namespace, folding this trial's bootstrap/teardown operational knowledge into [`docs/runbooks/darwin-bootstrap.md`](../runbooks/darwin-bootstrap.md), and regenerating `docs/desktop/keybinds.md` against the new registry shape. The same pass re-keys [`modules/darwin/yabai.nix`](../../modules/darwin/yabai.nix)'s header and [`modules/darwin/jankyborders.nix`](../../modules/darwin/jankyborders.nix)'s header (which still frames the module as bordering AeroSpace-tiled windows, and is directly cited by §Decision) down to a short pointer at this ADR — this ADR is the canonical home for the posture rationale (§Context), the module headers only point here. `docs/runbooks/yabai-trial.md` is deleted with the branch — its dated findings are graduated into §History below.

## History

The trial's findings log lived on the throwaway `trial/yabai` branch (`docs/runbooks/yabai-trial.md`, deleted at this ADR's implementation); its durable provenance is captured here, the way [ADR-040](./ADR-040-macos-window-manager-aerospace.md) §History preserved the `trial/aerospace` log.

- **2026-08-11 — activated on neptune, full keymap exercised.** (The host carried its prior celestial name at this point in the trial — ADR-045's re-key landed mid-trial, #804/#807.) The SIP-enabled claims documentation alone could not settle were confirmed on macOS 26.5.2: `window --space N` moves windows (`Hyper+Shift+1‑9`) — the load-bearing uncertainty, holding on Tahoe after 7.1.25's restoration of the non-SA path; `space --focus N` works via the synthesized gesture path — that synthesized-gesture switch was judged acceptable in day-to-day use (the runbook had predicted the verdict would turn on this, and it did not turn out to be the obstacle expected); `Hyper+1‑9` later moved to synthesizing the native Switch-to-Desktop shortcuts for the slide instead (§Decision, and the 2026-08-12 entry below). `window --toggle zoom-fullscreen` is a stable, reversible maximise, which AeroSpace could not offer at all, leaving #491/#492 open. Service mode was verified end to end: keystrokes reach no application while active, `r` (`space --balance`) and `f` (`window --toggle float`) both act and auto-return to `default` via a trailing `skhd -k escape` — the config's most fragile mechanism, verified separately from the actions themselves.
- **2026-08-11 — corrections this trial forced on its own runbook.** One Space existed pre-trial, not four; eight had to be created, not five, or the operator would have been left four Desktops short with a quarter of the keymap silently dead. Counting `uuid` keys in `com.apple.spaces` is not a valid Space count — it sweeps in `Collapsed Space` records for disconnected displays; the Main display's `Spaces` array is the only honest source. "Switch to Desktop N" was wrongly recorded as **off** by default; the correction established the shortcuts **are** on by default. The error came from probing the shortcuts while only one Desktop existed — `Ctrl+1` was already the current Desktop and Desktop 3 did not exist, so both probe chords were no-ops regardless of binding state — and a control test that appeared to clear the mechanism actually only proved skhd's own synthesis worked, saying nothing about macOS's own bindings. The lesson kept: **a negative result from a probe run against absent state is not evidence**, and — more generally — an absent `com.apple.symbolichotkeys` entry does not mean "enabled by default"; it means macOS has recorded no deviation, and the effective state can still be off.
- **2026-08-11 — observations carried forward.** `yabai -m query --windows` lists phantom window records (a hidden 1Password record with empty title/role and a stale frame) that at a glance read as untiled windows overlapping the layout; **`has-ax-reference`, not `is-visible`, is the correct discriminator** — `is-visible` means only "on a Space that is not currently visible" and is false for every window on every other Space, so filtering on it discards most of the real fleet rather than the phantoms. Service mode has no visual indicator — AeroSpace surfaced its active mode in the menu bar; yabai + skhd surface nothing while the mode captures the whole keyboard, the most likely future "the machine is wedged" moment and the sharpest usability regression found, carried forward unresolved. Native fullscreen suspends the edge-scroll wrap, accepted as-is: a native-fullscreen app takes its own Space at the end of the nine, so while it is open the wrap silently no-ops in one direction and steps into the fullscreen Space instead of wrapping in the other; nothing breaks, the plain step keeps working, and the operator confirmed and accepted both behaviours rather than guarding them in code.
- **2026-08-12 — first cold boot: everything came back except the borrowed shortcuts.** yabai, skhd, JankyBorders and SwiftBar all started, and every bind that talks to yabai directly worked — app launch, focus, move-column, move-window-to-workspace. What died was exactly the set that synthesizes a macOS shortcut: `Hyper+1‑9` and the edge-scroll's chords (step and wrap alike), 11 of 41 binds, because the entire Mission Control shortcut group had reverted to unticked — silently, no log line and no failed exit. A boot-time Accessibility race was first suspected and then withdrawn: `yabai.err.log` does hold an Accessibility-abort line, but its mtime was the trial's first start on 2026-08-11, before the grant was given — both cold boots wrote nothing to that log. Reading a log line without reading its timestamp had turned a day-old first-run message into an imagined boot-time race. Diagnosis on this host could not rely on synthesized keystrokes either: `skhd -k` from an interactive shell silently stopped posting events after the reboot, so every "the chord did nothing" reading taken that way was uninformative — one prompted a pointless skhd restart — and ground truth for a keybind is a finger on the key. Two `borders` processes appeared after the first boot and a single one after the second — a one-off, cause unknown, not investigated.
- **2026-08-12 — verdict: GO.** **yabai is adopted as celaeno's window manager**, superseding ADR-040's AeroSpace decision. Full substance graduated into §Rationale and §Consequences above.
